# 中国跳棋 · 人机对战

一个纯前端的 2 人中国跳棋（Chinese Checkers）Web 小程序：人类对战 AI，可在开局前选择**我先手**或**我后手**。无后端、无外部网络请求，构建后可作为静态站点部署。

## 功能

- 标准 121 孔六角星棋盘：中心六边形 61 孔 + 6 个营地各 10 孔。
- 2 人对战使用上、下两个对角营地，各 10 枚棋子。
- 完整规则：6 方向相邻单步、跳过相邻一子落入空位、连续跳跃（可转向、可在任意一跳后停止）、跳跃不吃子。
- 先后手选择：人类先手执红先走；人类后手时 AI 执红自动完成第一手。
- AI 三档难度（简单 / 普通 / 困难），每步思考不超过 2 秒；超时、异常、非法输出均有确定性兜底。
- 交互：选子、合法单步/跳跃高亮、连跳草稿路径与「结束回合」、最后一手标记、非法操作提示。
- 状态区：当前回合、手数、双方进营进度、AI 思考态、AI 降级提示、胜负/平局结果与重新开始。

## 环境要求

- Node.js ≥ 20
- npm ≥ 10

## 安装与运行

```bash
npm install       # 安装依赖（或 npm ci 使用 lockfile）
npm run dev       # 本地开发：http://127.0.0.1:5173
npm run build     # 类型检查 + 生产构建，输出 dist/
npm run preview   # 预览 dist/ 静态产物
```

构建产物 `dist/` 可被任意静态文件服务器托管，运行时不需要服务端、数据库或环境变量。

## 脚本

| 命令 | 说明 |
|---|---|
| `npm run dev` | 启动 Vite 开发服务器 |
| `npm run build` | `tsc --noEmit` + `vite build`，输出 `dist/` |
| `npm run typecheck` | TypeScript strict 类型检查 |
| `npm run preview` | 本地预览生产构建 |
| `npm test` | Vitest 单元测试（引擎 / AI / 控制器） |
| `npm run test:e2e` | Playwright 端到端测试（需先安装浏览器） |
| `npm run test:all` | 单元测试 + E2E |

首次运行 E2E 前安装浏览器：

```bash
npx playwright install chromium webkit
```

E2E 用例位于 `tests/e2e/`（由测试角色提供）；Playwright 会自动执行构建并启动静态预览服务。

## 玩法

1. 在开始界面选择 AI 难度与先后手，点击「开始对局」。
2. 轮到人类时，点击己方棋子；棋盘会高亮：
   - **实心圆点**：合法单步落点；
   - **空心环**：合法跳跃落点。
3. 点击单步落点立即完成回合；点击跳跃落点进入连跳草稿：
   - 仍有后续跳跃时，可继续点击空心环，或点击「结束回合」；
   - 没有后续跳跃时自动结束回合；
   - 若某一跳使己方占满目标营，立即获胜（即使还有后续跳跃）。
4. 任意一方 10 枚棋子全部进入对方初始营地即获胜；无合法着法自动轮空；双方连续轮空或达到 300 手为平局。

规则细节：

- 跳跃可跨越任意颜色的一枚棋子，被跨越的棋子不移除。
- 一次连跳只计 1 手；连跳可随时停止，停止不是「不完整路径」。
- 目标营可自由进出，不启用进营锁定。
- 对局中可随时「重新开始」（保留设置）或「返回设置」。

## AI 难度

| 难度 | 行为 |
|---|---|
| 简单 | 1 层贪心评估，节奏快 |
| 普通 | 2 层对抗搜索，会防守并阻挡对手一步获胜 |
| 困难 | 迭代加深 alpha-beta（可配置深度），时间预算内搜索更深 |

所有难度共用硬约束：只输出合法着法；存在一步获胜时必选获胜着法；普通/困难在对手存在一步获胜威胁且存在化解着法时必须化解；单步思考 ≤ 2 秒。超时/异常/非法输出时按「已算出的最佳着法 → 随机合法着法 → 轮空」兜底；连续 3 次降级后本局自动降为简单难度并显示提示。

## 项目结构

```text
.
├── index.html
├── src/
│   ├── main.ts              # 应用入口
│   ├── types/               # 契约类型与错误模型
│   ├── engine/              # 棋盘、规则、状态机、PRNG（无 DOM）
│   ├── ai/                  # 评估、alpha-beta 搜索、AI 客户端
│   ├── ui/                  # 控制器、SVG 棋盘、DOM 绑定、测试钩子
│   └── styles/              # 设计令牌与响应式样式
├── tests/                   # Vitest / Playwright 用例（测试角色提供）
├── vite.config.ts
├── playwright.config.ts
└── package.json
```

分层约束：`engine` 不依赖 `ai`/`ui`/浏览器 API；`ai` 只依赖 `engine`；`ui/controller` 不引用 DOM，可在 Node 中直接单测。

## 测试钩子

仅当 URL 含有 `?e2e=1`（如 `/?e2e=1`）时，页面会暴露 `window.__CC_TEST__`，用于加载固定局面、读取状态、注入 AI 失败模式。生产构建不创建该对象。

## 浏览器支持

Chrome / Edge / Safari 最近两个大版本。Playwright 配置覆盖 Chromium 与 WebKit；不支持 IE 与旧版 Edge。

## 已知限制（本期范围）

- 仅 2 人（人类 vs AI），不支持 3/4/6 人、联网、观战、账号。
- 不支持存档/读档、悔棋、棋谱、计时器、音效、主题切换、国际化。
- 刷新页面会丢失当前对局（无持久化）。
- 不提供完整键盘对局（方向键选点）；按钮与弹层操作键盘可达。
- 测试由外部测试角色提供；仓库内的单元测试覆盖引擎、AI 与控制器核心路径。
