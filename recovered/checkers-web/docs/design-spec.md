## 0. 范围、基线与设计决策

### 0.1 文档关系

```
prd.md（规则/需求，冻结）
  └─ acceptance-criteria.md（AC-01 ~ AC-51，冻结）
       ├─ design-spec.md（本文件：视觉 / 交互 / DOM / 响应式 / 无障碍）

            ├─ S4 UI 实现
            └─ S5 / S6 / S8 测试实现
```

- 规则真值（棋盘、合法着法、胜负、轮空、手数）**只来自 PRD §4 与规则引擎**。本文件不重新定义规则，只定义如何呈现与操作。
- 任何视觉/交互数值若与 AC 冲突，以 AC 为准；本文件在 §12 给出逐条映射。

### 0.2 本期范围

**包含**

- `SETUP` 开始界面：难度（简单/普通/困难，默认普通）、先后手（我先手/我后手，默认我先手）、开始对局。
- 对局界面：SVG 121 孔棋盘、20 枚棋子、选子、合法单步/首跳落点、连跳草稿与「结束回合」、最后一步、AI 思考态、进营进度、手数、轮空/降级提示。
- `GAME_OVER` 结果弹层：红方获胜 / 蓝方获胜 / 平局；重新开始；返回设置。
- 响应式：360×640 至 1440+；Chrome / Edge / Safari 最近两个大版本。
- 基础无障碍：键盘可达按钮、`aria-live` 状态、颜色非唯一信息、`prefers-reduced-motion`、触控命中 ≥24px。

**不包含（PRD §2.2）**

- 多人 / 联网 / 账号 / 排行 / 观战；悔棋；存档/读档；棋谱；计时器；音效；主题切换；国际化。
- 键盘完整对局（方向键选点）——本期不实现；所有按钮与弹层操作必须键盘可达。
- 进营锁定、禁手等可选房规。
- 持久化：刷新允许丢失对局（PRD §10.4）。

### 0.3 设计决策记录（DD）

| 编号 | 决策 | 理由 / 边界 |
|---|---|---|
| DD-01 | 棋盘使用 **内联 SVG** 矢量渲染，不做 Canvas | PRD FR-16 要求 SVG 或等价矢量；SVG 便于 DOM 可测（121 个孔位）、缩放清晰、无 DPR 处理 |
| DD-02 | 单一浅色「纸感」主题，不提供主题切换 | PRD 非目标；减少主题切换带来的对比度风险与验收成本 |
| DD-03 | 棋盘 viewBox 固定 `-300 -340 600 680`，孔距 `S = 44` 逻辑单位；外层 CSS 等比缩放 | 与 PRD §4.1.6 投影公式一致；一个 viewBox 同时服务桌面与移动 |
| DD-04 | UI 的 phase 是引擎 phase 的超集：`SETUP / HUMAN_TURN / AI_THINKING / GAME_OVER` | PRD §4.5.1；引擎只区分 `PLAYING / FINISHED`，AI 思考与开始界面属于控制器/UI |
| DD-05 | 连跳采用「一跳一操作、草稿路径」，提交给引擎的始终是完整路径；完整路径以**实际停止点**为准（单跳后停止合法） | PRD §4.4.1 / §4.4.3；AC-08 允许任意一跳后停止；引擎独立校验整条路径 |
| DD-06 | 轮空全自动，不提供「轮空」按钮 | PRD §4.5.2：轮空不得由玩家或 AI 主动选择 |
| DD-07 | 重新开始/返回设置**不做二次确认**，立即生效 | AC-24/25/26 要求立即生效；AI 旧结果用 `gameId` 代际校验丢弃 |
| DD-08 | AI 决策异步化：Worker 或 ≤50ms 合作式时间片；控制器另设 1950ms 兜底看门狗 | PRD §7.2.6 要求思考期 UI 可响应；§7.3 要求 AI 自身超时保护；看门狗是防御性兜底，不替代 AI 自限时 |
| DD-09 | 连跳草稿期间引擎局面不变；UI 以 `selection.current` 渲染草稿棋子，并隐藏原点棋子 | 保证「未提交的连跳」不污染引擎状态；提交时一次性应用完整路径 |
| DD-10 | 同一局部测试定位只允许一个 `data-testid`；终局弹层使用 `result-*` 变体 | 避免 Playwright strict mode 命中多个元素；详见 §10 |
| DD-11 | 不使用 `alert/confirm/prompt`；所有提示为非阻塞 toast 或弹层 | PRD §8.4 |
| DD-12 | 不引入第三方 UI/图标/字体库；图标内联 SVG，字体使用系统字体栈 | PRD FR-37 / FR-41；零外部请求 |

## 1. 设计原则

1. **规则可信优先于装饰**：棋盘、落点、回合、胜负必须一眼可辨；动效不得遮挡或改变逻辑状态。
2. **棋盘是唯一视觉焦点**：桌面端棋盘占据主视觉面积；状态与操作在侧栏/下方，不与棋盘争夺注意力。
3. **每一步都有反馈**：选子、可落点、跳跃中点、连跳路径、最后一步、轮空、AI 降级、终局均有明确反馈。
4. **进攻性克制**：红/蓝棋子使用低饱和但可区分的材质色；选中/落点使用玉色与金色两种语义色，不堆叠高饱和色块。
5. **可测即设计**：关键元素、状态文案、坐标、`data-testid` 在实现前固定；测试可只凭契约与本节定位。
6. **尊重选择**：人类先手/后手在开局前明确可选；AI 思考期人类仍可重新开始或返回设置。

## 2. 信息架构与页面结构

### 2.1 三种界面

| 界面 | 对应 phase | 内容 | 可见性 |
|---|---|---|---|
| 开始界面 | `SETUP` | 标题、难度、先后手、开始按钮、规则摘要 | 仅 `SETUP`；对局开始后从 DOM 移除或 `hidden` |
| 对局界面 | `HUMAN_TURN` / `AI_THINKING` / `GAME_OVER` | 顶栏、状态卡、棋盘、连跳条、进营进度、操作区、页脚 | 非 `SETUP` |
| 结果弹层 | `GAME_OVER` | 结果标题、原因、手数/难度/执子摘要、重新开始、返回设置 | 仅 `GAME_OVER` |

- `SETUP` 与对局界面互斥；结果弹层叠加在对局界面上方，棋盘与状态保留在背景中（可见但锁定）。
- 所有界面共用顶栏品牌区；移动端顶栏压缩为 40–44px。

### 2.2 桌面布局（≥1024px）

![桌面布局线框](assets/layout-desktop.svg)

**网格**

```css
.game-layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 360px;
  grid-template-areas:
    "board turn"
    "board progress"
    "board actions"
    "board info";
  column-gap: 32px;
  row-gap: 16px;
  align-items: start;
  padding: 24px 48px;
}
```

- `board` 区域为左列，包含棋盘与连跳条；棋盘水平居中。
- `turn` / `progress` / `actions` / `info` 为右栏四张卡；卡间距 16px。
- 顶栏 64px；页脚 36px；主区最小高度按 `100dvh - 100px` 计算。
- 棋盘宽度：

```css
.board-frame {
  width: min(100%, 620px, calc((100dvh - 150px) * 600 / 680));
  aspect-ratio: 600 / 680;
}
```

> 1280×720 下棋盘约 **503×570 CSS px**；1440×900 下约 **620×703**。棋盘始终完整可见，不被视口裁切。

- 右栏卡片：
  1. **状态卡**：行动方/思考态、手数、难度、执子；`data-testid="turn-indicator"`。
  2. **进营进度**：红方/蓝方各 10 段进度与 `x/10`。
  3. **操作卡**：重新开始、返回设置。
  4. **对局信息**：难度、执子、连跳条说明。
- 连跳条默认不占空间；进入连跳草稿后出现在棋盘下方，高度 44px。

### 2.3 平板与移动布局

![移动端布局线框](assets/layout-mobile.svg)

| 断点 | 布局 | 棋盘宽度 | 状态卡位置 | 操作 |
|---|---|---|---|---|
| 360–719px | 单列 | `100%`（360px 视口下 336px） | 棋盘上方 | 进度、操作在棋盘下方；信息卡隐藏 |
| 720–1023px | 单列/两列混合 | `min(100%, 560px)` | 棋盘上方通栏 | 进度与操作并排；信息卡通栏 |
| ≥1024px | 两列（棋盘 + 360px 右栏） | 见 §2.2 公式 | 右栏顶部 | 右栏纵向排列 |
| ≥1440px | 两列（棋盘 + 380px 右栏） | 最大 620px | 右栏顶部 | 同上，页边距 48px |

**移动端（360×640）实测预算**

| 区域 | 高度 |
|---|---:|
| 顶栏 | 44 |
| 主区上下内边距 | 8 + 8 |
| 状态卡 | 52 |
| 棋盘 | 381（336 宽 × 600/680 比例） |
| 进营进度 | 44 |
| 操作 | 44 |
| 卡片间距（3×8） | 24 |
| **合计** | **605** |

- 360×640 下状态卡 + 棋盘 + 进度 + 操作全部在首屏内；连跳条出现时页面可纵向滚动 ≤52px，棋盘仍完整可见。
- 不允许横向滚动：`body { overflow-x: hidden; }`；所有宽度使用 `min(100%, …)`。
- 横屏/极短视口：保持棋盘宽度不缩小到命中区 <24px；允许纵向滚动，不裁切棋盘。

**层叠顺序（z-index）**

| 层 | z-index | 说明 |
|---|---:|---|
| 棋盘底板/孔位/棋子 | 0–10 | SVG 内部顺序，见 §4.6 |
| 选中/落点/路径标记 | 20–30 | 在棋子上方，但不遮挡点击命中层 |
| 孔位命中层 | 40 | 透明命中圆，位于最上层 |
| 连跳条 | 50 | 普通文档流/吸底 |
| Toast 提示 | 60 | 不阻塞点击 |
| 结果弹层遮罩 | 70 | 拦截棋盘与右栏点击 |
| 结果弹层卡片 | 71 | 焦点陷阱 |

### 2.5 焦点与首屏

- 首屏直接渲染 `SETUP`；不做启动动画/加载页。
- 点击「开始对局」后：
  - 人类先手：焦点移动到棋盘 SVG（`tabindex="0"`），读屏播报「对局开始，你的回合，红方」。
  - AI 先手：焦点移动到棋盘 SVG（锁定态），由状态区 `aria-live` 播报「对局开始，AI 思考中，蓝方」。
- `GAME_OVER`：焦点移动到结果标题（`tabindex="-1"`）；关闭弹层后焦点回到棋盘 SVG 或开始按钮。
- 返回设置：焦点回到「开始对局」按钮。

## 3. 视觉系统

### 3.1 色彩令牌

以 CSS Custom Properties 落地（实现文件建议 `src/ui/styles.css`）：

```css
:root {
  --cc-bg:            #F3EFE6;  /* 页面背景 */
  --cc-surface:       #FBF8F1;  /* 卡片/面板 */
  --cc-surface-2:     #F0EADD;  /* 次级控件/空进度段 */
  --cc-ink:           #22262B;  /* 主文字 */
  --cc-muted:         #6B665C;  /* 次要文字 */
  --cc-line:          #DDD5C6;  /* 分割线/描边 */

  --cc-gold:          #B7822F;  /* 选中环/最后一手（图形） */
  --cc-gold-strong:   #8E5F14;  /* 焦点/链接/大字号 */
  --cc-gold-text:     #6F470B;  /* 金色底上的小字 */
  --cc-gold-soft:     #F2E3C4;

  --cc-jade:          #2F6B5E;  /* 主按钮/你的回合/合法落点 */
  --cc-jade-dark:     #275A4F;
  --cc-jade-soft:     #DCEBE5;

  --cc-blue:          #3C6E9F;  /* 蓝方棋子/蓝方文字 */
  --cc-blue-strong:   #2F5A85;
  --cc-blue-soft:     #E2EBF4;

  --cc-red:           #C4473B;  /* 红方棋子/红方文字 */
  --cc-red-strong:    #A33A2D;
  --cc-red-soft:      #F6E3DF;

  --cc-danger:        #A63A2E;  /* 错误/失败 */
  --cc-board:         #E9DABC;  /* 棋盘木色 */
  --cc-board-edge:    #B9A585;
  --cc-hole:          #B7A276;  /* 孔位 */

  --cc-focus:         #8E5F14;
  --cc-focus-ring:    rgba(183, 130, 47, .35);
  --cc-shadow-card:   0 12px 32px rgba(58, 46, 30, .10);
  --cc-shadow-modal:  0 24px 64px rgba(34, 38, 43, .22);
}
```

**使用规则**

- 金色 `--cc-gold` 只用于**图形**（选中环、最后一步、路径、焦点环辅助），不用于小字号正文；小字号金色文字使用 `--cc-gold-text`。
- 红/蓝棋子色是**棋子本体**；红/蓝文字优先使用对应色（对比度已满足 4.5:1）。
- 玉色 `--cc-jade` 是交互主色：主按钮、选中/合法落点、「你」胶囊。
- 金色与玉色同时出现时，金色表示「历史/选中」，玉色表示「可操作」。形状同时区分（见 §4.5）。
- 语义色不唯一承载信息：每个颜色状态都有文字/形状/`aria-label` 辅助。

| `#8E5F14` on `#FBF8F1` | 5.21:1 | 金色小字 |
| `#6F470B` on `#F2E3C4` | 6.41:1 | 金色底上的小字/徽标 |
| `#6B665C` on `#F0EADD` | 4.76:1 | 次级文字/胶囊 |
| `#A63A2E` on `#FBF8F1` | 6.06:1 | 错误文字 |
| `#C4473B` on `#FBF8F1` | 4.59:1 | 红方文字 |
| `#3C6E9F` on `#FBF8F1` | 5.05:1 | 蓝方文字 |

### 3.2 字体与字号


| 角色 | 字号/行高 | 字重 | 字体 | 用途 |

| 开始页主标题 | 32/1.2 | 600 | display | `SETUP` 标题 |
| 区块标题 | 20/1.3 | 700 | ui | 状态卡、结果标题 |
| 卡片标题 | 16/1.4 | 700 | ui | 进营进度、对局信息 |

- 所有数字使用 `font-variant-numeric: tabular-nums`，避免手数跳动。

### 3.3 间距、圆角与阴影

- **间距**：4px 基准：`4 / 8 / 12 / 16 / 24 / 32 / 48`。卡片内边距 16–20；卡片间距 16；页面边距桌面 48、平板 24、移动 12。
- **圆角**：按钮/输入 10；卡片 16；弹层 24；胶囊 999；棋孔/棋子正圆。
- **阴影**：
  - 卡片：`0 12px 32px rgba(58,46,30,.10)`
  - 弹层：`0 24px 64px rgba(34,38,43,.22)`
  - 棋子：`drop-shadow(0 3px 2.4px rgba(58,42,24,.34))`
  - 焦点：`0 0 0 3px var(--cc-focus-ring)` + `outline: 2px solid var(--cc-focus)`
- **命中区**：按钮/可点击控件最小 44×44 CSS px；棋盘孔位命中直径 ≥24 CSS px（见 §4.7）。

### 3.4 图标与动效令牌

- 图标：内联 SVG，24×24 viewBox，`stroke: currentColor`，线宽 1.8；不使用外部图标库。
- 动效令牌：

```css
--cc-ease-out: cubic-bezier(.2, .8, .2, 1);
--cc-ease-in-out: cubic-bezier(.4, 0, .2, 1);
--cc-dur-fast: 120ms;
--cc-dur-step: 170ms;
--cc-dur-hop: 110ms;
--cc-dur-modal: 200ms;
--cc-dur-toast: 2000ms;
```

- `prefers-reduced-motion: reduce` 时所有位移/缩放/脉冲时长设为 0ms，直接呈现终态；仅保留透明度切换。

## 4. 棋盘几何与渲染规范

### 4.1 坐标与屏幕投影

规则坐标使用 PRD §4.1 的立方坐标 `(x, y, z)`，恒满足 `x + y + z = 0`；121 个孔位集合 `B` 与营地定义见 PRD §4.1.2 / §4.1.3。

屏幕投影采用 PRD §4.1.6 的公式，取：

```
S = 44                 // 相邻孔位中心距（逻辑单位）
X = 44 · (x + y / 2)   // 等价于 PRD：X = cx + (2x + y) · S/2
Y = −44 · (√3 / 2) · y // 等价于 PRD：Y = cy − y · S·√3/2
```

- 原点 `(0,0,0)` 位于棋盘正中心；`y = +8` 在屏幕上方（上营/蓝方），`y = −8` 在下方（下营/红方）。
- 逆投影（用于点击命中）：

```
u = X / 44
v = −Y / (44 · √3 / 2)
y = v
x = u − v / 2
z = −x − y
```

取最近整数孔位，并校验该三元组在 `B` 内。

- 投影只影响视觉，不影响规则真值；引擎坐标不得因渲染而改变。

### 4.2 尺寸、viewBox 与比例

| 项 | 值 |
|---|---|
| SVG viewBox | `-300 -340 600 680` |
| 宽高比 | `600 : 680` ≈ `1 : 1.1333` |
| 孔位中心距 `S` | 44 逻辑单位 |
| 全部孔位范围 | `X ∈ [−264, 264]`，`Y ∈ [−304.84, 304.84]` |
| 计算边距 | 左右 36，上下 35.16（用于星形底板与营地标签） |
| 孔位半径 | 8 |
| 棋子半径 | 16 |
| 孔位命中半径 | 22（= S/2，相邻命中圆相切） |
| 棋盘底板 | 六角星，外接半径 `4√3·S ≈ 304.84`，内半径 `4S = 176`，整体缩放 1.05 |

- CSS 使用 `width: 100%; height: auto; aspect-ratio: 600 / 680;`。SVG 内部不做 DPR 处理（矢量天然清晰）。
- 桌面端棋盘宽度按 §2.2 公式；移动端 360px 视口下棋盘宽 336px，`S_css = 336/600×44 = 24.64px`，命中直径 24.64px（≥24）。
- 禁止对棋盘使用非等比缩放（`preserveAspectRatio="xMidYMid meet"` 默认值）。

**营地标签**

- 121 个孔位全部可见；孔位之间由网格线 + 孔位描边形成清晰边界。
- 孔位本身不显示坐标文字（避免拥挤）；坐标仅存在于 `data-*` 与 `aria-label`。
- 悬停（仅 `@media (hover:hover)`）：孔位描边加深、半径视觉上不放大（避免误判）；可选中棋子/合法落点由上层标记表达。

### 4.4 棋子

- 半径 16；中心与孔位中心重合。

### 4.6 SVG 结构与绘制顺序

```html
<svg viewBox="-300 -340 600 680" role="grid" tabindex="0" aria-label="中国跳棋棋盘，121 个孔位">
  <defs>…渐变/滤镜/箭头…</defs>
  <g id="board-plate">…星形底板…</g>
  <g id="camps">…上营/下营三角…</g>
  <g id="grid">…网格线…</g>
  <g id="holes">…17 个 <g role="row">，每行含该行的孔位…</g>
  <g id="last-move-path">…最后一手折线…</g>
  <g id="legal-markers">…单步点/跳跃环…</g>
  <g id="pieces">…20 个棋子 <g>…</g>
  <g id="draft">…连跳草稿棋子/路径/编号…</g>
  <g id="camp-labels">…营地胶囊…</g>
  <g id="hit-layer" aria-hidden="true">…121 个透明命中圆…</g>
</svg>
```

- 棋子组包含 `data-testid="piece-<x>_<y>_<z>"` 与 `data-color="R|B"`。
- 孔位包含 `data-testid="cell-<x>_<y>_<z>"`、`data-occupant="R|B|none"`、`data-selectable`、`data-target`。
- 标记元素可使用 `pointer-events: none`，避免拦截命中。
- 孔位按 `y` 行分组为 `<g role="row">`，每个孔位是 `role="gridcell"`；其 `aria-label` 包含坐标/占用/可选中/可落点状态。
- 命中层 `aria-hidden="true"`，避免读屏重复播报；棋子组也可 `aria-hidden="true"`，由孔位承载语义。
- 命中层元素**不得**再使用同名 `data-testid`，改用 `data-hit-for="<x>_<y>_<z>"`。**唯一 testid 规则见 §10。**

### 4.7 命中、缩放与触控

- 每个孔位命中圆半径 22 逻辑单位（`0.5S`），相邻圆相切不重叠。
- 指针事件优先落在命中层；命中层 `<circle>` 的 `fill="transparent"`、`pointer-events="all"`。
- 若点击未命中任何圆（例如两孔之间），BoardView 用逆投影取最近孔位；距离超过 22 逻辑单位则忽略（不发请求、不提示）。
- 360px 视口：命中直径 24.64 CSS px；1280×720：命中直径约 36px。
- 触控：棋盘与按钮 `touch-action: manipulation`；禁止双击缩放；不用 300ms 延迟。
- 指针 `cursor`：可选中棋子/合法落点 `pointer`；AI 思考/终局 `not-allowed`（或 `default`）；其他 `default`。
- 拖动/长按不产生走子；只有 `click`（或 `pointerup` 且未移动超过 6px）才触发。

### 4.8 连跳预览与动画

#### 4.8.1 连跳草稿渲染规则

当 `HumanSelection.mode === 'jumping'`：

1. **隐藏**引擎局面中位于 `selection.origin` 的棋子。
2. 在 `selection.current` 绘制草稿棋子（正常棋子 + 选中双环）。
3. 绘制 `origin → p1 → … → current` 的实线金色路径，并在每跳落点绘制编号徽标。
4. 在 `origin` 绘制 r=16 的虚线幽灵圆与「起点」小字（可选，避免遮挡）。
5. 高亮 `selection.jumps` 中的后续跳跃落点（空心环）。
6. **不显示**任何单步落点；连跳中不得改为单步。
7. 在棋盘下方显示连跳条：「连跳中 · 已跳 {k} 跳」+「结束回合」按钮。
8. 草稿期间引擎状态、`ply`、`turn` 均不变；只有提交时一次性应用完整路径。
9. **DOM 属性同步视觉**：草稿期间 `origin` 的 `data-occupant="none"`、`data-selected="false"`；`current` 的 `data-occupant` 为人类颜色、`data-selected="true"`；`piece-*` 使用 `current` 坐标。测试钩子 `getState().pieces` 仍返回引擎状态（origin 有子），与 `selection` 配合使用。

#### 4.8.2 自动结束与手动结束

| 条件 | 行为 |
|---|---|
| 点击跳跃落点后，`queryMoveOptions(next).jumps.length === 0` 且 `canEndTurn=true` | **自动提交**完整路径；`committedBy='auto-end'` |
| 点击跳跃落点后，`winningIfEndTurn=true` | **立即提交**当前路径并终局；即使存在后续跳也不继续（引擎合法着法已排除获胜后的延伸） |
| 仍有后续跳跃 | 保持草稿态；显示连跳条与「结束回合」 |
| 点击「结束回合」 | 提交当前完整路径；`committedBy='end-turn'` |
| 点击非高亮孔位/其他棋子 | 拒绝，局面不变，提示「连跳中只能继续跳跃或结束回合」 |

#### 4.8.3 动画

| 动作 | 时长/缓动 | 细节 | 减少动效 |
|---|---|---|---|
| 单步落子 | 170ms `--cc-ease-out` | 棋子沿直线移动，中点放大 1.06、阴影加深；落点孔位轻微高亮 | 直接落位 |
| 跳跃每一跳 | 110ms/跳 `--cc-ease-in-out` | 二次贝塞尔弧线，控制点上移 0.18S；中点放大 1.05；被跨越棋子脉冲环 1 次 | 直接落位 |
| 连跳草稿推进 | 110ms/跳 | 每点击一次落点立即播放该跳；路径与编号同步出现 | 直接更新 |
| AI 完整路径 | 每跳 90ms，总时长 ≤450ms | 依次播放；超过 5 跳时压缩为 60ms/跳；最后落点轻微停顿 60ms | 直接落位 |
| 最后一手路径 | 240ms 画入 | `stroke-dashoffset` 画入；保持 .55 透明度 | 直接显示 |
| 选中环 | 120ms | 透明度 0→1 + 缩放 .92→1 | 直接显示 |
| 合法落点 | 120ms 淡入，最多 200ms 完成 | 按距离选中棋子由近到远错峰 12ms | 直接显示 |
| 连跳条出现 | 160ms | 高度/透明度；出现在棋盘下方（普通流），不覆盖棋盘；移动端页面可纵向滚动 | 直接显示 |
| 结果弹层 | 200ms | 遮罩淡入；卡片 scale .96→1 + translateY 8→0 | 直接显示 |
| Toast | 160ms 进入，2000ms 停留，160ms 退出 | 上移 8px + 淡入；不阻塞点击 | 直接显示/消失 |
| AI 三点 | 1200ms 循环 | 透明度/位移循环；`aria-hidden` | 静态「…」 |

**动画约束**

- 动画只改变视觉，不改变逻辑状态；快照是唯一真值。
- 单次动画不得连续占用主线程 >16ms；优先 CSS transform/opacity；路径插值使用 `requestAnimationFrame`，每帧 ≤8ms 计算。
- 动画期间棋盘输入：人类走子提交后立即进入 AI 回合，本来已锁定；连跳草稿的每一跳动画 ≤110ms，期间忽略重复点击（`animating` 本地锁）。
- 连跳点击落点时 BoardView 立即启动**单跳**动画；若该跳自动结束回合（`auto-end`），提交后只收尾该跳，不重放整条路径；`end-turn` 不启动新动画。
- `prefers-reduced-motion` 时全部动画 0ms；不显示跳跃弧线/路径画入，但保留最后一手标记与路径静态显示。

## 5. 交互状态机

### 5.1 phase 与 UI 子状态

| phase | 含义 | 棋盘输入 | 可用操作 |
|---|---|---|---|
| `SETUP` | 开始界面 | 无棋盘 | 难度、先后手、开始对局 |
| `HUMAN_TURN` | 轮到人类 | 可选子/落子 | 选子、单步、跳跃、结束回合（仅连跳）、重新开始、返回设置 |
| `AI_THINKING` | AI 计算中 | **锁定** | 重新开始、返回设置（可中止 AI） |
| `GAME_OVER` | 已分胜负/平局 | 锁定 | 结果弹层中的重新开始、返回设置 |

`HUMAN_TURN` 内部子状态（不改变 phase、`ply`、`turn`）：

| 子状态 | 触发 | UI 表现 | 退出 |
|---|---|---|---|
| `idle` | 人类回合，未选子 | 无选中环/落点 | 点击己方有走法棋子 → `selected` |
| `selected` | 选中己方有走法棋子 | 选中双环 + 单步点 + 首跳环 | 点击落点 → 提交/`jumping`；点击另一己方棋子 → 切换；点击已选棋子/Esc → `idle` |
| `jumping` | 已执行 ≥1 次跳跃但未提交 | 草稿棋子 + 路径 + 后续跳环 + 连跳条 | 继续跳；结束回合；自动结束；获胜立即终局 |

### 5.2 主状态迁移

```
SETUP --开始对局（我先手）--> HUMAN_TURN
SETUP --开始对局（我后手）--> AI_THINKING --AI 首手--> HUMAN_TURN
HUMAN_TURN --完整回合结束（未终局）--> AI_THINKING
AI_THINKING --AI 落子/轮空（未终局）--> HUMAN_TURN
HUMAN_TURN / AI_THINKING --胜负/平局--> GAME_OVER
GAME_OVER --重新开始--> HUMAN_TURN（人类先手）或 AI_THINKING（AI 先手）
任意非 SETUP --返回设置--> SETUP
任意非 SETUP --重新开始--> 新对局（按当前设置）
```

| 当前 phase | 事件 | 下一 phase | 副作用 |
|---|---|---|---|
| `SETUP` | 开始对局，人类先手 | `HUMAN_TURN` | `gameId+1`；初始局面；`ply=0`；`turn=R`；焦点到棋盘 |
| `SETUP` | 开始对局，人类后手 | `AI_THINKING` | 同上；AI 执红；350ms 后开始计算 |
| `HUMAN_TURN` | 单步提交 | `AI_THINKING` 或 `GAME_OVER` | 应用走子；`ply+1`；清空选中；记录最后一手 |
| `HUMAN_TURN` | 跳跃/连跳提交 | `AI_THINKING` 或 `GAME_OVER` | 应用完整路径；`ply+1`；清空草稿 |
| `HUMAN_TURN` | 无合法着法 | 自动轮空 → `AI_THINKING` 或 `GAME_OVER` | 棋盘不变；`ply+1`；提示轮空 |
| `AI_THINKING` | AI 合法走子 | `HUMAN_TURN` 或 `GAME_OVER` | 应用走子；`ply+1`；清除思考态 |
| `AI_THINKING` | AI 无合法着法 | 自动轮空 → `HUMAN_TURN` 或 `GAME_OVER` | 棋盘不变；`ply+1`；提示轮空 |
| `AI_THINKING` | 重新开始 | 新局 `HUMAN_TURN` / `AI_THINKING` | `gameId+1`；中止并丢弃旧 AI 结果 |
| `AI_THINKING` | 返回设置 | `SETUP` | `gameId+1`；中止 AI；保留设置 |
| `GAME_OVER` | 重新开始 | 新局 | `gameId+1`；重置；AI 先手则自动首手 |
| `GAME_OVER` | 返回设置 | `SETUP` | `gameId+1`；保留设置 |

### 5.3 选子 → 落点 → 单步 / 连跳

**选子**

1. 仅 `HUMAN_TURN`；仅人类颜色；仅当该棋子有至少 1 个合法着法。
2. 点击后调用 `queryMoveOptions(state, piece)`：
   - `steps` = 所有合法单步落点；
   - `jumps` = 所有合法首跳落点（去重）；
   - 两者都为空 → 不进入选中态，提示「该棋子没有可走的路线」。
3. 选中态高亮：单步=实心点；首跳=空心环；可同时显示。
4. 点击另一枚有走法的己方棋子 → 切换选中；旧高亮清除。
5. 点击已选中棋子 / `Esc` → 取消选中（仅 `selected` 子状态）。

**单步**

1. 点击 `steps` 中的落点。
2. 控制器提交 `{piece: origin, path: [target], kind: 'step'}`。
3. 引擎校验并应用；`ply+1`；回合切换；清空选中；显示最后一手路径与标记。
4. 若落子使己方占满目标营 → 立即 `GAME_OVER`（见 §5.6）。

**跳跃与连跳**

1. 点击 `jumps` 中的落点 → 草稿推进一跳；若 `winningIfEndTurn` → 立即提交并终局。
2. 若还有后续跳 → 保持 `jumping`，显示连跳条与「结束回合」。
3. 若没有后续跳 → 自动提交（`committedBy='auto-end'`）。
4. 点击「结束回合」→ 提交当前路径（`committedBy='end-turn'`）。
5. 连跳中：
   - 只能点击后续跳跃落点或「结束回合」；
   - 不得切换棋子、不得单步、不得回退；
   - 点击其他棋子/非高亮孔位 → 提示「连跳中只能继续跳跃或结束回合」。
6. 一次连跳只计 1 手；每一跳不切换回合。**提交给引擎的「完整路径」以实际停止点为准**：只跳第一跳后点「结束回合」是合法的完整回合；「不完整」仅指路径几何上缺跳/不连续，不是「本可以多跳但选择停止」。
7. 若某一跳使己方占满目标营 → 立即终局，后续跳不得执行（引擎合法着法已排除）。

### 5.4 点击分派矩阵

| 当前子状态 | 点击对象 | 结果 | 提示 |
|---|---|---|---|
| `idle` | 对方棋子 | 不选中 | 「请选择己方棋子」 |
| `idle` | 空格 | 不选中 | 「请选择一枚棋子」 |
| `idle` | 己方无走法棋子 | 不选中 | 「该棋子没有可走的路线」 |
| `idle` | 己方有走法棋子 | `selected` | — |
| `selected` | 己方另一有走法棋子 | 切换选中 | — |
| `selected` | 己方无走法棋子 | 保持原选中 | 「该棋子没有可走的路线」 |
| `selected` | 已选中的棋子 | 取消选中 | — |
| `selected` | 单步落点 | 提交单步 | — |
| `selected` | 首跳落点 | 进入 `jumping` 或提交 | — |
| `selected` | 非高亮孔位/对方棋子 | 状态不变 | 「不可落子」 |
| `jumping` | 后续跳跃落点 | 推进/提交 | — |
| `jumping` | 「结束回合」 | 提交当前路径 | — |
| `jumping` | 其他己方棋子 | 状态不变 | 「连跳中只能继续跳跃或结束回合」 |
| `jumping` | 非高亮孔位 | 状态不变 | 「连跳中只能继续跳跃或结束回合」 |
| `AI_THINKING` | 棋盘任意位置 | 忽略（不改变状态） | 无（状态区已显示思考中） |
| `GAME_OVER` | 棋盘任意位置 | 忽略 | 无（弹层已显示结果） |

- 提示为非阻塞 toast，约 2s 自动消失；同一提示重复触发时重置计时，不叠加多个 toast。
- `AI_THINKING` / `GAME_OVER` 的棋盘点击**静默忽略**（PRD §8.3），不弹提示。
- 点击未命中任何孔位（孔间空白）直接忽略。

### 5.5 AI 思考态

进入 `AI_THINKING` 时：

1. 立即清除人类选中/草稿；锁定棋盘（`pointer-events: none` 于命中层，或控制器拒绝所有点击）。
2. 状态卡显示 **「AI 思考中 · {红方/蓝方}」** 及三点动画（视觉上等价于「AI 思考中…」）；`data-testid="ai-thinking"`；状态卡 `aria-live="polite"` 播报一次。
3. 棋盘 `aria-busy="true"`、`aria-disabled="true"`；已显示的最后一手/终局标记保留；孔位仍可被读屏浏览但不能操作。
4. 「重新开始」「返回设置」仍可用；点击后立即中止 AI（`gameId+1`，旧结果丢弃）。
5. AI 在 350ms 后开始计算；从进入思考态到落子应用完成 ≤2000ms（契约 §6.3）。
6. AI 落子后：动画播放完整路径（若走子），`ply+1`，状态切换为 `HUMAN_TURN` 或 `GAME_OVER`。
7. AI 无合法着法：自动轮空，显示「{红方/蓝方}无可行着法，自动轮空」，`ply+1`，回到人类回合；若双方连续轮空 → 平局。
8. AI 降级：状态卡下方出现非阻塞提示「AI 已降级为简单难度」，持续到本局结束；不弹窗、不阻塞。

**UI 不得**

- 不显示进度百分比/假进度条（AI 可能在 350ms 内返回）。
- 不因 AI 思考而禁用「重新开始」「返回设置」。
- 不在 AI 思考态响应任何棋盘点击。

### 5.6 结算、轮空、重新开始、返回设置

**胜负**

- 任意方 10 枚棋子占满对方初始营地 → 立即 `GAME_OVER`。
- 结果标题：`红方获胜` / `蓝方获胜` / `平局`。
- 副标题（人类视角）：
  - 人类获胜：「恭喜，你赢了」
  - AI 获胜：「再接再厉」
  - 平局：「本局平局」
- 原因文案：
  - 占满目标营：「占满对方营地 10 孔」
  - 连续轮空：「双方连续无可行着法」
  - 300 手：「达到 300 手上限」
- 终局后棋盘锁定；选中/落点全部清除；保留最后一手路径与标记；获胜方目标营加金色高亮。

**轮空**

- 无合法着法时自动发生，玩家/AI 不得主动选择。
- 提示：「{红方/蓝方}无可行着法，自动轮空」，2s。
- 轮空计 1 手；双方连续两回合轮空 → 平局；有合法着法的一方走子后计数清零。
- 轮空后若对方为 AI → 进入 `AI_THINKING`；若对方为人类 → 进入 `HUMAN_TURN`。

**重新开始**

- 立即生效，无确认；`gameId+1`；保留当前难度与先后手；棋盘重置为初始局面；`ply=0`。
- 人类先手 → `HUMAN_TURN`；AI 先手 → `AI_THINKING` 并自动首手。
- 若正在连跳草稿/选中：清除草稿，不提交。
- 若 AI 正在思考：中止并丢弃旧结果；新局若 AI 先手，只应用新局的 AI 首手。

**返回设置**

- 立即生效，无确认；中止对局与 AI；`gameId+1`；回到 `SETUP`。
- 保留上次难度/先后手选择，可修改；不自动开局。
- 从 `GAME_OVER` 返回设置同样适用。

### 5.7 并发与过期结果

- 每次开始/重开/返回设置都生成新 `gameId`。
- AI 请求携带 `gameId`、`turn`、`ply`；响应返回时逐项校验；任何不匹配 → 丢弃，不改变 UI。
- 同一时刻最多一个 AI 请求在飞；旧请求的定时器/Worker 被取消或忽略。
- 快速连点：控制器在 `AI_THINKING` 拒绝棋盘输入；人类回合的重复点击由当前子状态与合法落点校验兜底；不得产生两次提交。
- 页面隐藏/恢复：若 AI 看门狗因后台节流延迟，恢复可见时立即检查截止时间并应用兜底着法（契约 §6.4）。

## 6. 组件规格

### 6.1 按钮

| 类型 | 外观 | 尺寸 | 用途 |
|---|---|---|---|
| 主按钮 | 实心 `--cc-jade`，白字 14/700，圆角 10 | 高 44，最小宽 120，水平内边距 20 | 「开始对局」「重新开始」（对局中）、结果弹层「再来一局」 |
| 次按钮 | `--cc-surface` 底 + 1.5px `--cc-jade` 描边 + 玉色字 | 高 44 | 「返回设置」「结束回合」 |
| 幽灵按钮 | 无底/无描边，玉色字 | 高 40 | 次要取消/说明链接（如需要） |
| 危险按钮 | 不使用 | — | 本期无删除/破坏性操作 |

- 所有按钮为原生 `<button type="button">`；`disabled` 时透明度 .45、`cursor: not-allowed`；禁用按钮保留 `data-testid`。
- `:focus-visible`：2px `--cc-focus` + 3px `--cc-focus-ring`；不得移除 outline。
- 按钮内图标 16–18px，与文字间距 8px；图标 `aria-hidden="true"`。
- 按下态：`transform: translateY(1px)`；`prefers-reduced-motion` 时取消。

### 6.2 单选卡片（难度 / 先后手）

- 结构：`<fieldset>` + `<legend>` + 2–3 个 `<label>` 包裹原生 `<input type="radio">`（视觉隐藏但可聚焦）。
- 卡片：`--cc-surface` 底、1.5px `--cc-line` 描边、圆角 12、内边距 14–16；最小高度 84（难度）/ 72（先后手）。
- 选中：1.5px `--cc-jade` 描边 + `--cc-jade-soft` 背景 45% + 右上角玉色对勾圆（r=9，白色对勾）；文字/描述保持高对比。
- 未选中：`--cc-line` 描边；hover 时描边加深。
- 键盘：原生 radio 支持方向键切换；`Tab` 进入组；`input:focus-visible + label` 显示与按钮一致的焦点环，不得只隐藏 input 的焦点。
- 难度卡片文案：
  - 简单：「节奏快，适合熟悉规则」
  - 普通：「会防守，默认推荐」
  - 困难：「搜索更深，思考 ≤2 秒」
- 先后手卡片文案：
  - 我先手：「执红 · 下营 · 你先走」
  - 我后手：「执蓝 · 上营 · AI 先走」

### 6.3 状态卡（`turn-indicator`）

- 桌面：右栏第一张卡，内边距 20，最小高度 132。
- 移动：棋盘上方，高度 52，单行紧凑。
- 结构：
  - 左侧 7px 圆点表示**当前行动方颜色**（红方=红、蓝方=蓝）；AI 思考时另加三点动画；终局时人类胜=金色、AI 胜=muted、平局=红蓝双色半圆。
  - 主文案：`你的回合 · 红方` / `你的回合 · 蓝方` / `AI 思考中 · 红方` / `AI 思考中 · 蓝方`（后接三点动画；可访问名称「AI 思考中…」）。
  - 副文案：`第 {ply} 手 · {生效难度}难度 · {我先手/我后手}`；连续降级后生效难度显示「简单」并加「已降级」小字。
  - 右侧「你」胶囊（人类回合，`--cc-jade-soft` 底 + `--cc-jade` 字）或「AI」胶囊（AI 回合，`--cc-surface-2` 底 + `--cc-muted` 字）。
- `data-testid="turn-indicator"`；主文案放在 `data-testid="turn-text"` 内，便于精确断言。
- 仅主文案 `turn-text` 容器设 `aria-live="polite"`；每次 phase/行动方变化播报一次；副文案/进度不重复播报。
- `GAME_OVER` 时状态卡显示「对局结束」，不再显示「轮到…」，避免终局背景误导。
- AI 三点动画：`AI 思考中` 后三个点依次淡入淡出；`aria-hidden`；文字本身已足够。

### 6.4 进营进度

- 两行：红方、蓝方；每行 `x/10` + 10 段进度条。
- 颜色：红行 `--cc-red`，蓝行 `--cc-blue`；未填充段 `--cc-surface-2` + 1px `--cc-line`。
- 段尺寸：桌面 24×8，间隔 1；移动端紧凑为 5px 段（两组并排）。
- 文案：`红方进营` / `蓝方进营`；数值 `data-testid="progress-red"` / `progress-blue`，内容严格为 `{n}/10`。
- 进度条 `role="progressbar"`、`aria-valuemin="0"`、`aria-valuemax="10"`、`aria-valuenow="{n}"`、`aria-label="红方进营进度"`。
- 人类一方行末加「你」小胶囊；AI 一方加「AI」。

### 6.5 连跳条与「结束回合」

- 仅 `HumanSelection.mode='jumping'` 显示；位于棋盘正下方，高 44，卡片式。
- 内容：左侧「连跳中 · 已跳 {k} 跳」+ 路径缩略（可选）；右侧主按钮「结束回合」。
- `data-testid="jump-bar"`；按钮 `data-testid="end-turn"`；状态文本 `data-testid="jump-status"`。
- 出现/消失 160ms；不改变棋盘尺寸（桌面）；移动端可纵向滚动。
- 「结束回合」在 `canEndTurn=true` 时可用；本期进入 `jumping` 后恒为 true。
- AI 回合/终局不显示连跳条。

### 6.6 提示 Toast（`hint`）

- 位置：棋盘下方/页面底部居中；移动端在棋盘下方 12px。
- 外观：`--cc-surface` 92% + 1px 描边 + 阴影；圆角 12；内边距 10×14；14px 正文；左侧 16px 图标（信息/警告/错误）。
- `role="status"`、`aria-live="polite"`；同一时刻只显示一条；2s 自动消失；进入/退出 160ms。容器常驻、无提示时文本为空并视觉隐藏（`opacity:0`），**不要**用 `hidden` 移除，以免读屏错过更新。
- 不阻塞点击；不推动布局（`position: fixed` 或棋盘下方绝对定位）。
- 文案见 §9.3。

### 6.7 结果弹层

- 遮罩：`rgba(34,38,43,.38)` + `backdrop-filter: blur(6px)`；点击遮罩不关闭。
- 卡片：宽 `min(420px, calc(100vw - 32px))`；圆角 24；内边距 28；`--cc-surface`；阴影 modal。
- 内容：
  - 顶部结果图标（胜=金色奖杯/星形；负=蓝色棋子；平=双色圆环）。
  - 标题（20–24/700）：`红方获胜` / `蓝方获胜` / `平局`。
  - 副标题（14）：人类视角文案。
  - 原因（12 muted）。
  - 摘要行：`第 {ply} 手 · {难度}难度 · {我先手/我后手}`。
  - 按钮：主「再来一局」、次「返回设置」；移动端纵向排列，桌面横向。
- `role="dialog"`、`aria-modal="true"`、`aria-labelledby="result-title"`、`aria-describedby="result-desc"`。
- 焦点陷阱：`Tab`/`Shift+Tab` 在弹层按钮间循环；`Esc` 不关闭（避免误操作）；打开时对背景 `header/main/footer` 设置 `inert`（或 `aria-hidden="true"`），仅弹层可交互；关闭后移除。
- 打开时焦点到标题，关闭后焦点回棋盘 SVG/开始按钮。
- 终局背景：棋盘降低不透明度 .72；获胜方目标营金色高亮；不显示任何可落点/选中环。

### 6.8 AI 降级提示

- 非阻塞横幅/胶囊，位于状态卡下方或连跳条上方；`data-testid="ai-degraded-notice"`。
- 文案：「AI 已降级为简单难度」；可加一行小字「本局剩余时间生效」。
- 颜色：`--cc-gold-soft` 底 + `--cc-gold-text` 字；左侧信息图标。
- 连续 3 次降级后出现，持续到本局结束（重开重置）；不自动消失。
- 不得使用 `role="alert"` 打断；使用 `role="status"` + `aria-live="polite"`。
- 降级后状态卡/对局信息卡的难度显示切换为**生效难度**（简单），并在旁边标注「已降级」；重开时恢复用户配置难度（`configuredDifficulty`）。

### 6.9 开始界面（`SETUP`）

- 容器：`data-testid="setup-panel"`；最大宽度 720；居中；上下留白 48/32。
- 结构：
  1. 品牌/标题：「中国跳棋」32/600 display；副标题「与 AI 对战，先手后手由你决定」14 muted。
  2. 规则摘要一行：「六方向移动 · 可连续跳跃 · 占满对方营地 10 孔获胜」12。
  3. 难度组：`<fieldset>` + 3 张单选卡；`data-testid="difficulty-easy|normal|hard"`。
  4. 先后手组：2 张单选卡；`data-testid="side-first|side-second"`。
  5. 主按钮「开始对局」：`data-testid="start-game"`；全宽（移动）/ 240px（桌面）。
  6. 次要说明：「AI 每步思考不超过 2 秒；本地运行，不联网。」11 muted。
- 默认选中：难度 `normal`，先后手 `first`。
- 切换选项即时更新选中态；开始按钮始终可用；点击后不出现阻塞弹窗。
- 键盘：`Tab` 依次进入两组 radio 与开始按钮；方向键切换组内选项；`Enter/Space` 触发开始。
- 对局开始后 `SETUP` 从 DOM 移除（或 `hidden` + `display:none`），避免重复 testid。

### 6.10 顶栏与页脚

- 顶栏：左「中国跳棋」（24/600 display），次行/右侧「2 人 · 人机对战」；右侧胶囊「本地 AI · 不联网」（`--cc-gold-soft` 底 + `--cc-gold-text` 字）。
- 对局中顶栏不再显示难度/先后手（已在状态卡与信息卡）。
- 页脚（桌面/平板）：「规则摘要：六方向单步 · 连续跳跃 · 跳跃不吃子 · 占满对方营地 10 孔获胜」12 muted；移动端隐藏页脚。
- 顶栏/页脚不参与棋盘交互，不设置快捷键。

## 7. 响应式规范

### 7.1 断点与布局

| 断点 | 布局 | 顶栏 | 主区内边距 | 棋盘最大宽 | 右栏/卡片 |
|---|---|---|---:|---:|---|
| `< 720px` | 单列 | 44px | 8px 12px | `100%`（≤520） | 状态卡在上；进度/操作在下；信息卡隐藏 |
| `720–1023px` | 单列混合 | 56px | 24px | 560px | 状态卡通栏；进度/操作并排；信息卡通栏 |
| `1024–1439px` | 两列 | 64px | 24px 48px | 按高度公式（≤620） | 右栏 360px |
| `≥1440px` | 两列 | 64px | 24px 48px | 620px | 右栏 380px |

### 7.2 尺寸计算

- 棋盘比例固定 `600:680`；宽度由容器与高度共同约束：

```css
.board-frame {
  width: min(100%, 620px, calc((100dvh - 150px) * 600 / 680));
  aspect-ratio: 600 / 680;
  margin-inline: auto;
}
```

- `100dvh` 不可用时回退 `100vh`：

```css
@supports not (height: 100dvh) {
  .board-frame { width: min(100%, 620px, calc((100vh - 150px) * 600 / 680)); }
}
```

- 360×640 下棋盘 336×381；768×1024 下棋盘 560×634；1280×720 下约 503×570；1440×900 下 620×703。
- 不得使用固定像素棋盘尺寸；不得在窄屏隐藏任何孔位/棋子。

### 7.3 响应式行为

- 窄屏：状态卡上移，操作区下移；连跳条紧贴棋盘下方。
- 触控：孔位命中 ≥24px；按钮 ≥44px；不使用 hover-only 功能作为唯一入口。
- 横屏：保持棋盘比例；若高度不足，允许纵向滚动；不压缩到命中区 <24px。
- 200% 浏览器缩放：按有效 CSS 视口进入单列；布局不横向溢出。
- 文本放大：按钮/卡片高度使用 `min-height` 而非固定 `height`；允许文案换行，不截断。
- 安全区：`padding-bottom: max(16px, env(safe-area-inset-bottom))` 用于移动端底部操作区。

### 7.4 移动端紧凑规则

- 状态卡 52px：主文案 16/700 + 右侧手数 11；难度/先后手移入对局信息（移动端隐藏）或状态卡副文案压缩为「第 12 手 · 普通」。
- 进营进度 44px：两组文本 + 两组 10 段微型进度条并排（红 3/10、蓝 5/10）。
- 操作 44px：两个按钮等宽并排，分隔线 1px。
- 连跳条 44px：文本 + 「结束回合」按钮；不覆盖棋盘。
- 页脚隐藏；品牌标题缩小到 16–18px。

## 8. 无障碍规范

### 8.1 语义与结构

- `<html lang="zh-CN">`；`<meta name="color-scheme" content="light">`。
- 语义地标：`header`、`main`、`footer`；开始界面 `section[aria-labelledby]`；对局状态 `section`；结果弹层 `div[role=dialog]`。
- 标题层级：h1（品牌）、h2（开始页/状态/结果）、h3（卡片标题）；不跳级。
- 棋盘 SVG：`role="grid"`、`tabindex="0"`、`aria-label="中国跳棋棋盘，121 个孔位"`；孔位按 `y` 行分组为 `role="row"`，每格 `role="gridcell"`；焦点在 SVG 上可获得整体说明；每格 `aria-label` 包含坐标/占用/状态，不单独进入 Tab 序列（本期不做完整键盘对局）。
- 所有交互控件为原生 `<button>`/`<input type="radio">`；不使用 `div` 模拟按钮。

### 8.2 焦点

- 可见焦点：2px `--cc-focus` + 3px `--cc-focus-ring`；暗色背景上同样可见。
- 焦点顺序：开始界面（难度组 → 先后手组 → 开始按钮）→ 对局（棋盘 SVG → 重新开始 → 返回设置 → 连跳条按钮）。状态卡通过 `aria-live` 播报，不作为焦点停靠点；棋盘内部孔位不单独 Tab。
- 结果弹层打开时焦点陷阱；关闭后回焦触发元素/棋盘 SVG。
- AI 思考/动画期间不移动焦点；不强制焦点跳转。

### 8.3 状态播报（`aria-live`）

| 事件 | 播报 |
|---|---|
| 对局开始 | 「对局开始。你的回合，红方。」 / 「对局开始。AI 执红，思考中。」 |
| 走子 | 「红方走了一步。」 / 「蓝方连跳 2 跳。」 / 「AI 走了一步。」 |
| 轮空 | 「红方无可行着法，自动轮空。」 |
| 选中 | 「已选中红方棋子，第 x 行第 y 列。可落子 5 处，可跳跃 1 处。」（使用人类可读坐标或序号；不要求 cube 坐标） |
| 终局 | 「对局结束，红方获胜。」 / 「对局结束，平局。」 |
| 降级 | 「AI 已降级为简单难度。」 |
| 提示 | 同 Toast 文案（`role=status`） |

- 使用一个视觉隐藏的 `#sr-status`（`aria-live="polite"`、`aria-atomic="true"`）承载事件播报；避免与状态卡的 `aria-live` 重复播报。
- 结果弹层标题可聚焦，打开时读屏直接朗读；不需要额外 `alert`。
- 状态卡负责回合/思考态播报；`#sr-status` 负责走子/轮空/选中/结果等事件；二者不得重复播报同一句。

### 8.4 颜色与形状

- 选中/落点/最后一手/胜负均使用「颜色 + 形状 + 文字」三重编码。
- 红/蓝棋子颜色不是唯一信息：状态区始终写「红方/蓝方」「你/AI」；孔位 `aria-label` 含颜色。
- 链接/按钮不使用仅颜色区分（下划线/描边/形状辅助）。
- 高对比模式（`forced-colors: active`）：
  - 使用 `CanvasText`/`Canvas` 系统色；为选中/落点增加 2px 实线描边；
  - 营地标签/棋子保留 `forced-color-adjust: auto`；
  - 金色/玉色差异可能丢失，形状与文字仍可辨。

### 8.5 动效与触控

- `prefers-reduced-motion: reduce`：关闭位移、缩放、脉冲、路径画入；保留瞬时状态切换。
- 闪烁频率 <3Hz；无自动播放音效。
- 触控目标：按钮 ≥44×44；孔位命中 ≥24×24；相邻命中圆不重叠。
- 文本可缩放至 200% 不截断；不使用 `user-scalable=no`。

### 8.6 已知边界（与 PRD 一致）

- 本期不提供完整键盘对局（PRD §2.2 非目标）；方向键选点、棋盘内逐孔 Tab 不实现。
- 屏幕阅读器可获知棋盘状态/回合/结果与所有按钮，但通过读屏完成整局不在验收范围。
- 不保证 IE/旧 Edge；目标浏览器见 PRD §9。

| `aria-label` | 例：「孔位 -4,5,-1，红方棋子，可选」「孔位 0,0,0，空，可跳跃」 |

**棋子 `piece-*`**

| 属性 | 值 |
|---|---|
| `data-color` | `R` / `B` |
| `data-last-move` | `true` 时表示最后一手终点 |
| `data-selected` | `true` 时表示选中/草稿 |
| `aria-hidden` | 棋子本身可 `aria-hidden="true"`，由孔位承载语义（如果棋子是 `<g>` 装饰） |

**棋盘容器**

- `aria-busy="true"` / `aria-disabled="true"` 仅 `AI_THINKING`；`GAME_OVER` 时棋盘 `aria-disabled="true"`。
- `data-phase` = `SETUP|HUMAN_TURN|AI_THINKING|GAME_OVER`（便于测试读取）。
- `data-game-id` = 当前 `gameId`（便于测试断言重开）。

### 10.5 唯一性与稳定性

- 同一时刻，每个 `data-testid` 在文档中最多出现一次。
- `SETUP` 与对局界面互斥：开始后 `setup-panel` 移除/隐藏；`start-game` 不再存在。
- `GAME_OVER` 时 HUD 的 `restart-button`/`back-to-setup` 仍在 DOM（弹层遮罩拦截点击）；终局操作使用 `result-*`，两者不重复。
- 孔位/棋子 testid 使用坐标，不依赖 DOM 层级；坐标负号必须是 ASCII `-`（U+002D）。
- 文案变更不得改变 testid；testid 变更视为契约变更，需 designer + tester 确认。

## 11. 动效与性能

### 11.1 渲染策略

- 单 SVG，121 孔 + 20 棋子 + 标记，DOM 节点约 200–300；一次性创建孔位/网格，后续只更新属性/`transform`。
- 状态变化时重绘：棋子位置、标记、状态卡、进度；不重建整个 SVG。
- 不做常驻 `requestAnimationFrame` 循环；动画期间才启用 rAF。
- 不使用 Canvas/WebGL；不使用外部字体/图片/图标库。
- 棋盘缩放完全由 CSS/SVG viewBox 完成；窗口 resize 不需要重新计算坐标。

### 11.2 性能预算

| 项 | 目标 |
|---|---|
| 首屏（本地静态服务） | ≤1s（P1 要求 ≤2s） |
| 人类点击到界面反馈 | ≤100ms（PRD P1） |
| 落子动画 | ≤450ms（AI 多跳） |
| AI 思考主线程占用 | 连续 ≤50ms；推荐 Worker |
| 单帧脚本 | ≤8ms（动画插值） |
| 总 DOM | <500 节点 |
| 网络请求 | 仅同源静态资源；零外部请求 |

- 动画使用 `transform`/`opacity`；不触发布局。
- 棋子/标记更新使用 `setAttribute('transform', …)` 或 CSS 变量，避免整树重排。
- 大列表（121 孔）使用文档片段一次性挂载。
- 事件委托：棋盘容器一个 `click` 监听，按 `data-testid`/坐标分派，避免 121 个监听器。
- 页面隐藏时暂停 CSS 动画；AI 看门狗在恢复可见时校验截止时间。

### 11.3 减少动效

- `prefers-reduced-motion: reduce`：所有动画 0ms；不显示跳跃弧线、路径画入、三点循环；直接渲染终态。
- 动画不得作为唯一反馈：状态卡文案、最后一手标记、Toast 必须同步更新。
