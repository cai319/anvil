## 1. 走查范围与方法

### 1.1 范围

- **页面/状态**：`SETUP`、`HUMAN_TURN`（空态/选中/连跳草稿）、`AI_THINKING`、`GAME_OVER`（红胜/蓝胜/平局）、重新开始、返回设置、AI 降级提示、非法操作提示。
- **两种开局**：人类先手（执红/下营）与 AI 先手（人类执蓝/上营）。
- **核心交互**：选子、合法单步、合法跳跃、连跳（结束回合/自动结束/获胜立即终局）、非法点击、AI 思考锁定、最后一步、进营进度、手数。
- **响应式**：1280×720、1440×900、768×1024、360×640；横向溢出、棋盘裁切、触控命中。
- **基础无障碍**：键盘 radio、焦点环、`aria-live`、结果弹层焦点陷阱/`inert`、`prefers-reduced-motion`、颜色非唯一信息。

### 1.2 方法

1. 使用 S4 产出的 `dist/` 静态托管，未重新构建、未修改任何源码。
2. 通过真实 UI 点击完成开局、选子、落子、AI 应手、重开/返回；通过 `?e2e=1` 测试钩子（契约 §8）加载 PRD 附录 B 的夹具 A/C，并构造等价的「AI 先手 / 蓝方终局」夹具，以覆盖终局与两跳边界（避免在走查中等待完整的 300 手对局）。
3. 用 Playwright 记录 DOM/快照/边界框/计算样式；截图保存到 `artifacts/ux-review-2026-10-19/`。
4. 对每个问题记录：复现步骤、预期（设计规格条款）、实际（数值/截图）、严重级别、修正建议。

## 3. 走查记录（可复现）

### 3.1 人类先手

1. `SETUP` 默认「普通 / 我先手」；开始后 `phase=HUMAN_TURN`、`turn=R`、`ply=0`、20 子、121 孔。
2. 选 `(1,-5,4)`：`selection.steps` 2 个、`jumps` 0；DOM `data-target` 与 `legal-step-*` 完全一致；7 枚红子可选中、3 枚无走法不可选。
3. 点击 `(1,-4,3)`：`ply=1`、进入 `AI_THINKING`；状态「AI 思考中 · 蓝方」、三点、`aria-busy=true`、`aria-disabled=true`；AI 思考中点击 `(0,0,0)` 不改变 ply/turn/phase。
4. AI（注入 delay 1200ms）在 1573ms 内完成应手（合法 jump）；`ply=2`、最后一步路径/虚线环/金点正确、进度 0/10。
5. 夹具 C：选 `(0,0,0)` → 5 个单步点 + 1 个首跳环；点击 `(2,-2,0)` 进入 `jumping`：`ply` 仍 40、原点 `data-occupant=none`、当前 `R`、路径/跳号/后续跳环/结束回合均正确；点击另一红子提示「连跳中只能继续跳跃或结束回合」。
6. 结束回合：`ply=41`、`lastMove.path=[(2,-2,0)]`、`committedBy=end-turn`、进入 AI；另一路径点击 `(2,0,-2)` 自动结束：`path` 两跳、`committedBy=auto-end`。
7. 夹具 A：选 `(-3,4,-1)`，5 个单步点含唯一获胜点 `(-4,5,-1)`；点击后 `GAME_OVER`、红方 10/10、`ply=81`、结果弹层「红方获胜 / 恭喜，你赢了 / 占满对方营地 10 孔 / 第 81 手 · 普通难度 · 我先手」；胜营 `cc-camp-top` 高亮；焦点在标题、背景 `inert`、Tab 陷阱、Esc 不关闭。
8. 「再来一局」：`gameId 1→2`、`ply=0`、20 子、弹层关闭、`inert` 移除；「返回设置」：`SETUP`、`config` 保留、焦点回开始按钮。

### 3.2 AI 先手

2. AI 首手（注入 delay 1000ms）在 1388ms 内完成合法单步；`ply=1`、`HUMAN_TURN`、人类执蓝可操作。

### 4.3 P2（建议进入 S7；若不在 S7 修复，需 PM 在 S10 明确接受）

#### P2-01 桌面连跳条出现时棋盘缩小并重新居中

- **复现**：1280×720，选子后点击首跳落点，使连跳条出现。
- **预期**：按 `design-spec.md` §4.8 / §6.5，连跳条出现在棋盘下方，不改变棋盘尺寸；棋盘保持 502.9×570、x=192.5。
- **实际**：棋盘缩为 **450×510**，x 从 **192.5 → 219**；连跳条仍为 620 宽，出现「条比棋盘宽」的视觉关系。连跳条出现前后棋盘整体缩放/重排，后续跳落点位置随之移动。
- **证据**：`02-game-human-first-1280.png` vs `07-jump-draft-1280.png`；实测 `board` rect 502.94×569.98 @ (192.53,88) → 450×510 @ (219,88)。
- **影响**：连跳是核心操作；棋盘在第一次跳跃后缩小 10.5%，会打断空间连续性，增加后续落点误判风险。
- **修正建议**：移除 `.game-layout.has-jump-bar .board-frame` 的宽度收缩；在棋盘下方预留 54px（或让连跳条覆盖在棋盘下缘/浮动），保持棋盘几何不变；若必须收缩，至少让 jump-bar 与棋盘同宽并明确动画过渡。建议进入 S7 修复。

#### P2-02 桌面 AI 降级提示被自动排到信息卡下方，越出首屏并覆盖页脚

- **复现**：1280×720，注入 AI 异常连续 3 次，触发 `forcedEasy`。
- **预期**：按 `design-spec.md` §6.8，提示位于状态卡下方或连跳条上方，非阻塞且可见。
- **实际**：`.degraded-notice` 作为 `.game-layout` 的额外网格项自动落到第二列 info 卡之后（`rect: x=872,y=674,w=360,h=58.8`）。1280×720 下其底部到 732.8，超出视口 12.8px，并与页脚（y=684..720）重叠；页面 `scrollHeight=793`。提示标题可见，副标题被裁切。
- **证据**：`16-ai-degraded-1280.png`；实测 `notice` 与 `info`、`footer` rect。
- **影响**：AI 降级是 PRD AC-37 要求的状态提示；位置漂移/页脚重叠削弱其可见性与收尾整洁度。
- **修正建议**：在桌面栅格中为提示显式指定 `grid-area`（状态卡下方）或将它渲染进 turn card；确保 1280×720 下完整可见且不与 footer 重叠；若 rail 变高，允许纵向滚动但提示必须在首屏。建议进入 S7 修复。

#### P2-03 1440×900 右栏卡片间距 71px（设计为 16px）

- **复现**：1440×900 打开对局界面，测量右栏 turn/progress/actions/info 卡片间距。
- **预期**：`design-spec.md` §2.2 规定 `row-gap: 16px`；卡片分组紧凑。
- **实际**：四张卡之间均为 **71px** 间距（turn 88..220、progress 291..418、actions 489..565、info 636..785），因为 `.game-layout` 的网格行被 702.7px 高的棋盘拉伸，rail 内容只有约 567px，剩余高度被分摊到行间。
- **证据**：`18-game-1440x900.png`；实测 `gaps {turnProg:71.09, progAct:71.09, actInfo:71.13}`。
- **影响**：右栏卡片失去「一组控制面板」的紧凑感，视觉上被拉散；1440 是设计目标视口。
- **修正建议**：`.game-layout { align-content: start; }` 或 `grid-auto-rows: min-content`；或把 rail 改为独立 flex column（`gap:16px`），让卡片在顶部紧凑排列。建议进入 S7 修复。

#### P2-04 360×640 开始页主 CTA 位于首屏折叠以下

- **复现**：360×640 打开 `SETUP`。
- **预期**：开始按钮作为主操作应完整可见；设计目标包含 360 宽度（`design-spec.md` §7.1 / §6.9）。
- **实际**：`start-game` rect `top=627.1, height=44, bottom=671.1`；视口 640，仅约 13px 可见；`scrollHeight=733`，用户需向下滚动约 31px 才能完整看到按钮与脚注。截图 `17-setup-360x640.png` 中看不到完整的「开始对局」。
- **影响**：首次进入的移动端用户可能误以为页面没有开始入口；这是获取用户的第一步。
- **修正建议**：在 ≤719px 将难度卡改为 3 列紧凑分段（当前 `.option-grid--difficulty` 为 `1fr`，三卡纵向 73px×3），或缩小卡片高度/上边距；也可让开始按钮 sticky 在底部。建议进入 S7 修复。

#### P2-05 360×640 连跳「结束回合」按钮 34px 高，低于 44px 设计最小触控

- **复现**：360×640，夹具 C 进入连跳草稿。
- **预期**：`design-spec.md` §3.3 / §6.1 规定按钮最小 44×44 CSS px；§6.5 连跳条高 44。
- **实际**：`end-turn` rect 82×**34**（y=504.7..538.7），位于 336×46 的连跳条内；触控目标偏小，且是连跳流程的必用按钮。
