# v1.62.1 修复：角色运行时临时目录与宿主会话环境

发布日期：2026-11-28　类型：patch

## 问题

从 agent shell（例如 Claude Code 会话）启动后端后，角色 agent 的 Bash 工具在 standard
Seatbelt 沙箱内启动即报：

```
EPERM: operation not permitted, mkdir '/private/tmp/claude-501/...'
```

Cindy 因此无法调用 `anvil task clarify`，只把草稿写进任务工作区的 `brief.json`；55 秒后
run 被 suspend，任务简报卡保持空白。这不是 v1.62 验收逻辑的问题，而是运行时环境不兼容。

## 根因（已用对照实验确认）

- Claude Code 原生 CLI 的项目临时目录默认固定为 `/private/tmp/claude-<uid>/<cwd-slug>`，
  **不跟随 `TMPDIR`**；standard Seatbelt 的写范围只包含工作区、角色 home、实例目录和
  `data/repos` 下的 git 元数据。
- 干净环境（`env -i`、独立 `TMPDIR`）与继承宿主环境都会落到同一路径，因此不是环境变量
  泄漏单独造成的。
- CLI 支持用 `CLAUDE_CODE_TMPDIR` 覆盖该路径；实验证明设置到沙箱实例 tmp 后 Bash 正常。
- 宿主会话变量（`CLAUDECODE`、`CLAUDE_CODE_CHILD_NOTES_DIR`、`CLAUDE_CODE_MESSAGING_*`、
  session/pid/execpath 等）不应带进角色进程，会指向沙箱写范围之外或改变嵌套会话行为。

## 修复

- 角色运行时环境设置 `CLAUDE_CODE_TMPDIR=<沙箱实例 tmp>`，`XDG_RUNTIME_DIR=<home>/.cache`。
- 剥掉宿主会话变量；兜底剥掉仍指向 `/Users/`、`/private/`、`/var/`、`/tmp/` 的
  `CLAUDE_CODE_*`。保留 Anvil 注入的模型/强度变量与 `ANTHROPIC_*` 凭证。
- `anvil sandbox self-check` 新增 `host_session_env` 检测：后端从 agent shell 启动时给出
  警告，但不再污染角色。
- 不放宽沙箱策略；standard 与 strict 档均可使用。

## 升级

1. 停止后端并备份 `data/`；
2. 更新代码/安装包并重启后端；本版无数据库迁移；
3. 执行 `anvil sandbox self-check`，确认 `profile_preflight=true`；`host_session_env` 非空
   只表示后端从 agent shell 启动，角色环境会自动清洗；
4. 重新构建前端：`cd frontend && npm run rebuild`。

## 验证

- 对照实验：干净/继承环境 × 无沙箱/standard；E5a 证明 `CLAUDE_CODE_TMPDIR` 可修好；
  Seatbelt deny 日志捕获到 `deny(1) file-write-create /private/tmp/claude-501/...`。
- 单元/集成：sandbox env / seatbelt / jobs 共 32 passed。
- 真实 Cindy run：EPERM 0 次，Bash 正常，`anvil task clarify` 成功，简报写入并等待 human。

## 已知限制

- `CLAUDE_CODE_TMPDIR` 未在 Claude Code 官方文档中，属于版本绑定的兼容性契约；CLI 升级后
  必须重跑金丝雀并更新兼容性矩阵（P0 后续）。
- 运行时环境失败目前仍可能表现为 run suspend；`runtime_env_error` fail fast 与金丝雀在
  P0 后续交付。
