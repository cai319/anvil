# Anvil v1.42.1 — 失败恢复与重启修复

> 发布日期：2026-11-10
> 版本：1.42.1

## 1. 修复失败 workflow step 的“重启进程”无效

失败步骤的真实状态是：

```text
run  -> failed
step -> pending / failed
step.run_id = NULL
step.next_retry_at = 退避时间
```

旧版重启只把 run 改回 `created`，没有恢复 step 的 `running/run_id/lease`，
下一轮 `_reap_orphaned_step_runs` 会立即把 run 再次标为
`failed / orphaned_step_run`。

修复：

- 新增 `workflow_service.check_step_run_restart`：
  - step running 且 run 匹配 → 普通重启；
  - step pending/failed/rejected → 允许 rebind；
  - step submitted/approved/skipped，或 workflow/task 终止 → 409。
- 新增 `workflow_service.rebind_run_to_step`：
  - 释放旧 lease；
  - 重新 acquire step lease/fence；
  - `step.status=running`、`step.run_id=run.id`；
  - 清 `next_retry_at/recovery_count/nudge_count`，decision 步骤清 `rework_count`。
- `POST /runs/{id}/restart|session-reset|full-reset` 在终止进程前先校验，
  重启后恢复 step 绑定，并清 `failure_class/ended_at/recovery_*`。

## 2. 普通 task/reply/dispatch run 的自动恢复

新增 `Scheduler._recover_failed_runs`：

- 只处理非 workflow step 的 failed run；
- 同一 `(role, task, slice)` 已有活跃/HITL run 时跳过；
- HITL、权限、范围、契约、人工取消等失败不自动重试；
- 指数退避，默认最多 3 次
  （`ANVIL_RUN_AUTO_RECOVER_MAX_ATTEMPTS`）；
- 第 2 次起自动换新 CIC（保留 MEMORY/知识快照）；
- 新 run 写入 `recovery_count/recovery_of_run_id` 和一次性失败说明 `wake_note`；
- 旧 run 写 `recovered_by`，避免重复恢复；
- 耗尽后写非阻塞 comment，不 @human；
- 超过 `ANVIL_RUN_AUTO_RECOVER_MAX_AGE_SECONDS`（默认 24h）的旧失败不再扫描。

开关：`ANVIL_RUN_AUTO_RECOVER=0` 可关闭。

## 3. 迁移

`schema.run_recovery_v1`：

```sql
runs.recovery_count INTEGER NOT NULL DEFAULT 0
runs.next_retry_at TEXT
runs.recovered_by TEXT
runs.recovery_of_run_id TEXT
runs.recovery_exhausted INTEGER NOT NULL DEFAULT 0
```
