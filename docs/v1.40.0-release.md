# Anvil v1.40.0 变更方案：任务上下文隔离 × 分层知识库 × 知识质量门

> 发布日期：2026-11-05
> 版本：1.40.0
> 范围：任务工作空间、上下文隔离、角色记忆、主题/任务/频道知识、经验捕获与收割、知识质量门、LLM 清洗、功能开关与反馈复核。

## 1. 目标

1. **任务上下文完全隔离**：不同任务不共享工作目录、投影文件或任务级知识。
2. **角色画像优先**：任务起始上下文以 system prompt、工作方式、skill/MCP 能力为主；历史知识只按 tag/相关性带入。
3. **知识与数据分离**：
   - Task Workspace 只负责任务数据；
   - Knowledge Repo 负责跨任务知识；
   - 任务级知识库位于 Task Workspace 内；
   - Channel / Role / Shared 继续作为上层知识作用域。
4. **知识可决策**：每条可批准知识必须有使用场景、具体作用、证据，并保持可读。
5. **自动化可控**：LLM 只做清洗/结构化/可读性辅助，不判定有效性、不自动批准、不编造证据。

## 2. 核心模型变更

### 2.1 Task Workspace

- 新增 `task_workspaces` 表与 `data/task-workspaces/<task-id>/`：
  - `work/`：代码/产物；
  - `knowledge/`：任务级知识库；
  - `drafts/`：任务级待批草稿；
  - `.anvil/workspace.json`：任务/来源元数据。
- 任务创建先登记，目录首次执行时懒创建。
- 支持 archive / mark_deleted / cleanup_stale；按保留天数清理归档任务，不清理 active 任务。
- `runs._create_worktree` 优先使用 `task_workspaces.source_repo`；旧 `tasks.repo` 不再承担执行仓库语义。

### 2.2 Workspace / Knowledge Repo / Channel 拆分

| 概念 | 存储 | 作用 |
|---|---|---|
| Task Workspace | `data/task-workspaces/<task-id>/` | 任务数据、任务级知识草稿 |
| 主题知识库 | `knowledge_repos` + `data/knowledge-repos/<repo>/` | 跨任务主题知识 |
| 任务级知识库 | `<workspace>/knowledge/<local-repo>/` | 当前任务私有知识 |
| Channel | `workspace_knowledge` + `data/channels/<id>/knowledge/` | 最高层知识收割 |
| Role | `PRINCIPLES.md` + `memory/cards/` + `notes/` | 角色私有长期经验 |
| Shared | `lessons` + `data/shared/lessons.md` | 跨角色公共经验 |

- 文件是真相，SQLite/FTS 是可重建索引。
- `repo_split_map` 记录旧 `tasks.repo` 到 workspace/source_repo/主题的迁移，可回滚。
- 迁移后真实库中主题注册表已物化，历史数据保持可读。

### 2.3 角色记忆

- 新增 `PRINCIPLES.md`（≤2KB 耐久准则，始终注入）。
- `memory append` 默认写角色经验卡 `memory/cards/<id>.md`；`--durable` 写准则。
- 不再整段注入 `MEMORY.md` 尾部；旧文件保留为 legacy 归档，可由 `memory compact` 拆分。
- 角色知识 `repo` 明确定义为“来源主题”，不是知识库绑定：
  - 写入时解析 canonical `repo_id`；
  - 历史记录按 alias/registry 回填；
  - 检索优先用 `repo_id`，旧数据回退名称匹配；
  - UI 显示“归属：角色私有”和“来源主题”。

### 2.4 任务上下文与可观测

- 延迟投影：持久会话在实际投递前才写 `CLAUDE.md` / `.claude`，避免任务间覆盖。
- Context manifest：记录 CIC/投影的层级、来源 ID、字符数、是否注入、丢弃原因。
- L0 能力清单：working mode、capabilities、skill/MCP 名称与一句话说明。
- 检索阈值 `KNOWLEDGE_MIN_SCORE`；空 query 不再返回最近笔记；当前任务 task-scoped 知识豁免阈值。
- 任务上下文预算 `TASK_CONTEXT_BUDGET_TOKENS=200000`，长任务提前轮换。

## 3. 知识产生与收割

### 3.1 任务知识

- 显式写入：任务详情「任务共享知识」、`anvil task knowledge-write`、API。
- 自动捕获（默认开启，可在工具页关闭）：
  - 完成 / 实质失败 / 返工 / 评审驳回；
  - 生成 `proposed` 任务级或主题级草稿；
  - 不读角色私有 notes，不调用 LLM，不自动批准；
  - `knowledge_captures` 幂等账本。
- 经验捕获现在生成结构化字段：
  - `use_when`、`expected_effect`、`evidence`；
  - 任务级 `task_finding` / 主题级 `insight` 的 kind 字段；
  - 不能推导的字段留空，由人工或 LLM 清洗补全。

### 3.2 主题知识库

- 自动绑定：按标题/描述/tags 匹配主题库；低相关时有主题信号则创建任务级知识库。
- 任务知识 → 主题库：人工晋升生成 `proposed`，原任务卡归档。
- 主题库 → Channel：人工收割生成频道 `proposed`。
- 主题库 → Shared：人工生成 `lesson pending`；不直接写 `data/shared`。
- 主题库支持 rename / merge / lock / alias；合并会迁移卡片、绑定和文本引用。

## 4. 知识质量门（v1.40.0 重点）

### 4.1 通用质量字段

- `use_when`：什么时候该用；
- `expected_effect`：具体作用/避免什么/改善什么；
- `evidence`：任务/步骤/run/文件/命令/评审结论；
- 可选：`preconditions`、`exclusions/counterexamples`、`effect_type`。
- 兼容旧字段：`scope/applicability/reuse_scope`、`outcome/consequences`。

### 4.2 质量评估

- 质量分 / grade / blocking / missing / warnings / dimensions。
- 维度：证据 30、场景 25、效果 25、可读性 20。
- 可读性：标题 ≤80、TLDR ≤200、正文 ≤4000；模糊措辞、原始日志堆叠、缺少边界给出警告。
- 质量分只用于排序和决策辅助，不替代人工。

### 4.3 审批硬门禁

- 主题知识卡：`repo_knowledge.approve` 校验 kind 必填 + 质量门。
- 频道知识：`workspace_knowledge.create/update/approve` 执行同一质量门。
- 任务 proposed 卡：`task_knowledge.approve` 执行质量门。
- 失败返回 `409`，detail 带 `quality.blocking`。
- 存量已批准卡标记 `legacy`，保留状态，不追溯撤销。
- 任务内 `active` 工作知识保留；晋升/主题审批仍必须过硬门禁。

### 4.4 编辑与展示

- `PATCH /knowledge/repo-cards/{id}`、`PATCH /tasks/{tid}/knowledge/{kid}`：
  - 人工补全 title/TLDR/fields/tags/authority；
  - 重新渲染正文、计算 completeness/quality、写版本快照。
- 主题知识库页：
  - 质量概览（平均分、覆盖率、kind 构成、legacy、待复核）；
  - 质量徽章、缺项徽章；
  - 「补全后批准」编辑器；
  - 任务/频道页签显示质量与缺项。
- 文件 frontmatter 保存 `fields`/review/completeness；reindex 不再丢字段。

## 5. LLM 知识清洗（默认关闭）

- 新开关：工具页「LLM 知识清洗」；配置 `ANVIL_KNOWLEDGE_LLM_CLEANING`。
- 人工按需：
  - 单卡预览字段/正文 diff、引用和清洗后质量；
  - 确认后写回 `proposed`；
  - 不自动批准、不改变 kind/authority/status。
- 规则：
  - 严格 JSON schema；
  - 新增/修改字段必须有原文引用；
  - 引用不成立的字段丢弃；
  - 找不到证据留空，不编造；
  - Utility 失败原卡不变；API 返回 502。
- API：`POST /knowledge/repo-cards/{id}/clean`。
- CLI：`anvil knowledge clean`。
- 规则门评估脚本：`dev/scripts/knowledge_quality_eval.py`。

## 6. 反馈、复核与过期

- 新表 `knowledge_feedback`：`applied/helpful/unhelpful/no_effect`。
- 主题卡行提供「有效/无效」反馈；到期卡提供「复核通过」。
- `GET /knowledge/review-candidates`：review_due/expired/legacy/negative_feedback/never_hit。
- `POST /knowledge/repo-cards/{id}/review`：keep/deprecate/refresh。
- 主题卡默认复核日期按 kind 计算；不自动删除/降级。

## 7. 功能开关与工具页

- 运行时开关注册在 `services/features.py`，持久化到 `settings`，启动时重新应用。
- 工具页开关：
  - 自动经验捕获（默认开）
  - LLM 知识清洗（默认关）
  - 主题知识库自动绑定（默认开）
  - 任务知识注入（默认开）
  - 频道知识注入（默认关）
  - 上下文来源清单（默认开）
  - 延迟投影（默认开）
  - 任务独立工作空间（默认开）
  - 工作空间自动清理（默认开）
- 开关旁只展示默认值；实际状态看开关。
- 人工改动写入 `audit`（`feature.toggle` / `feature.reset`）和运行时日志；治理页审计日志展示为：
  `功能开关 knowledge_repos → 开启`。
