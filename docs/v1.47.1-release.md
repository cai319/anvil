# Anvil v1.47.1 — 实时刷新与状态机补丁

> 版本：1.47.1（SSE 实时刷新、spawn 状态机、系统备注归属、workflow 子代理标记）
> 日期：2026-11-22

## 1. 为什么升级

v1.47.0 在收紧鉴权与状态 CAS 时引入两处回归：

1. 常驻进程投递时 daemon 已把 run 置为 `running`，`spawn_node` 的 CAS 必然失败，
   被误判为“并发终止”，刚拉起的角色进程在投递后约 20ms 被 `clear_run` 杀掉；
   任务派发后角色不工作，run 永久停在 `running` 且无进程。
2. `/api/v1/events` 改为只读 `X-Anvil-Session` 头，但浏览器 EventSource 只能把 token
   放在 query；中间件放行后依赖仍返回 401，导致全前端 SSE 实时刷新失效，侧栏收件箱
   角标等长期停留在打开页面时的快照。

本版本修复这两处回归，并补齐前端 SSE 韧性、计数面的统一刷新机制与若干 UI 修正。

## 2. 修复

### 2.1 spawn 状态机

- `spawn_node` 在 CAS 失败后回读 run 状态：只有已进入终态（completed/failed/abandoned）
  才 `clear_run` 并清空会话绑定；状态为 `running`（投递链路已提升）时保留刚投递的进程。
- 新增回归测试覆盖“投递提升 running 不误杀”和“并发终止仍清理”两种路径。

### 2.2 SSE 鉴权与客户端韧性

- 新增仅用于 `/events` 的 `get_event_auth`：允许 `?token=`，头优先；其他路由继续只认
  `X-Anvil-Session`，query token 不扩散。
- EventSource：CLOSED 连接不再复用；指数退避重连（1s→30s，±20% 抖动）；重连成功后
  发送合成 `connected` 事件供各组件补拉；单个订阅者异常不影响整条事件流。
- 新增 `useLiveRefresh`：topic/match 过滤、tick 节流、in-flight 合并、仅可见时轮询、
  `visibilitychange`/`focus` 恢复刷新。
- 接入：侧栏收件箱角标、顶部 Token/冻结、Inbox、Lobby、任务详情、角色运行时、
  FindingBoard/FindingDrawer、AgentSessions、RunSession、Channels、Knowledge 各页签、
  Reminders、Decompose、Governance。
- 后端补齐 action card / board draft 增删与审批的刷新事件；配置页与历史回放/档案页
  按设计保持快照。

### 2.3 UI

- 任务详情工作流页移除「套用模板」入口（创建任务页已可选择模板）；保留「保存为模板」
  与「规划种子」。
- 系统备注（`role_slug=NULL` 的 context note）不再显示为「你（自然人）」：改用系统
  机器人头像、作者与作用范围标记，正文去掉重复前缀。
- workflow 在带 `subagent_hint` 的阶段（验证/修复/复验）与步骤行显示“组织者→workers”
  图标；不显示数量，避免与“用了几个子代理”混淆。

## 3. 验证

- 后端：`pytest -q` — **1043 passed / 63 skipped**
- 前端：`npm run build` 通过
- 线上冒烟：
  - `GET /api/v1/events?token=<human>` → 200 + `event: connected` + 周期性 `tick`
  - `GET /api/v1/tasks?token=<human>` → 401（query token 仅限 events）
  - `GET /api/v1/events?token=bad` → 401
  - 收件箱角标与服务端 `GET /api/v1/inbox` 的 `count` 一致，处理待办后无需刷新即可更新

## 4. 升级注意

1. 重启后端以加载 SSE 鉴权与 spawn 补丁。
2. 重新构建前端（`cd dev/frontend && npm run build`）并刷新浏览器。
3. 若浏览器仍显示旧角标，刷新一次页面即可重新建立 SSE 连接；之后断线会自动重连。
