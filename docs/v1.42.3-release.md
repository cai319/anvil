# Anvil v1.42.3 — 当前运行会话选择与空白 run 日志说明

> 发布日期：2026-11-10
> 版本：1.42.3

## 1. 现象

角色运行时的“完整交互（上下文 / 模型 / 工具）”或运行详情的
`stdout/stderr` 偶尔只有一行：

```text
# run <id>  role=<role>  task=<task>  started=<time>
```

看起来像后台没有产生交互内容，过一段时间仍不更新。

## 2. 根因

这是两个不同原因叠加：

### 2.1 展示层选中了尚未投递的 run

`RoleSessions` / `TaskDetail` 之前按“当前切片的最后一个 run”或
“最后一个 step run”选择展示对象。调度器可能已经为并行分支、切片或
后续步骤创建了 run，但它仍在队列中，尚未真正投递给角色进程。
`create_run` 只写启动头，只有 `_send_locked` 真正投递时才写
`===== USER（上下文/提示词） =====` 和后续模型/工具事件。
因此：

- 后台实际交互在另一个正在执行的 run 上；
- 页面选中的 run 日志自然只有启动头。

修复：

- `RoleSessions` / `TaskDetail` 优先使用
  `roleRuntime.current_run_id`（且 `current_task_id` 等于当前任务）；
  没有当前 run 时才回退到切片 run、step run、最近 run。
- 这样活跃角色会展示真正在执行的会话，而不是排队中的新 run。

### 2.2 历史 run 没有采集 stdout

线上数据中 18 个只有启动头的任务 run 全部属于 2026-10-19 的同一个旧任务；
这些 run 有 `native_session_id`、生命周期迁移、mention 等活动记录，
说明后台确实执行过，只是当时的版本没有把 stdout/stderr 写入 run 日志。
2026-11-07 之后的 run 日志均为 6KB–170KB，采集正常。

修复：

- 新增 `runLog.ts::isHeaderOnlyRunLog`，识别“只有启动头”的日志。
- `RoleSessions` 与 `RunSession` 在空白日志上方显示明确说明：
  可能仍在排队/未投递，或为旧版本未采集日志的历史 run；任务时间线
  与活动记录仍可反映真实交互。
- 不伪造、不回填历史日志内容。

## 3. 验证

- 前端：`npx tsc --noEmit`、`npm run build` 通过。
- 线上库核对：
  - 只有启动头的任务 run：18 个，全部为 2026-10-19 旧 run；
  - 2026-11-07 之后的 run：日志均有实际内容。
- 后端全量测试沿用 v1.42.2 结果：781 passed, 58 skipped；
  本次仅前端展示逻辑改动，无后端/API 变更。
