# Anvil v1.50.1 — 任务会话默认「对话」与面向自然人的沟通规范

> 发布日期：2026-11-26
> 版本：1.50.1
> 分支：`rsi`

## 1. 版本主题

v1.50.1 是两个使用体验修复：

1. 任务会话默认只显示「对话」（评论与 @提及），减少 claim / submit / run / step 等
   编排事件对自然人的干扰；
2. 所有角色（含 Cindy）写给自然人的内容必须清晰、准确、自包含，交付件给出可直接
   打开的绝对路径，减少人机反复确认。

## 2. 任务会话默认「对话」

- `TaskDetail` 时间线筛选默认值由「全部」改为「对话」；「全部」仍可手动切换。
- 「对话」下没有内容时，空态会说明默认筛选，并提供「查看全部 N 条」按钮，
  避免把“没有对话”误判成“没有记录”。
- 切换任务时重新按默认「对话」展示；不做浏览器持久化。

## 3. 面向自然人的沟通

### 3.1 统一协议

新增 `HUMAN_COMMUNICATION_PROTOCOL`，要求所有写给 human 的文字（@human、请评审、
提交结果、解释诉求）遵守：

- 第一段先写结论和需要人类做什么，再给判断所需的最少背景；
- 用平实中文，正文不堆缩写、内部代号、JSON、日志、堆栈或内部 ID；
- 自包含，不写「见上文/同上/之前那条」；
- 需要决策时给出选项、各自后果、推荐和人类的最小动作，并说明批准/驳回后的下一步；
- 涉及交付件时按「交付件清单」写性质、内容简介与绝对路径；没有就写
  「本次无具体交付件」；
- 同一决策点只发一条整合消息，长度以人类一分钟能读完为准；
- 明确反例：「已完成」「方案已产出，请确认」不合格。

该协议注入普通任务、工作流步骤、回复、问题板与 Cindy 规划所有 run。
`DELIVERABLE_MANIFEST` 的适用范围从 submit 摘要扩展到 @human 回复与评审说明。

### 3.2 Cindy 规划

- 规划第三步 @human 必须写清：草案/角色建议与草案 id、任务目标与关键阶段、
  需要人类决定什么、各选项后果与推荐、批准/驳回后下一步、交付件或
  「本次无具体交付件（草案见 D-xxx）」，并给出合格示例。
- `--goal` 会直接显示在收件箱与草案审批页，要求用非技术语言说明目标；
  role_suggestion 的 `goal`/`assessment`/`description` 要说明“为什么需要这个角色、
  解决什么问题”。
- 新建 Cindy 的默认画像与角色生成提示词同步加入该规范；已有安装保留自定义
  system_prompt，现有角色通过运行时协议注入生效。

### 3.3 系统自动通知

- 普通任务提交、团队全部提交、工作流最终评审、决策重做次数耗尽、角色追加提案
  等 @human 通知，改为包含任务名、需要人类做什么、去哪里核对交付件清单。
- 最终评审通知不再对未启用问题板的任务谎称「问题板已就绪」；
  `transition_task` 状态竞争失败时不再重复 @human。
- 保留收件箱与测试依赖的关键子串（`工作流全部步骤完成`、`角色追加提案`）。

## 4. 文档与 CLI

- `docs/cli-reference.md` 新增「面向自然人的沟通」规则。
- `anvil` 主帮助、`anvil task`/`anvil step` 帮助与 `--summary`/`--to` 说明补充
  人类可读要求。
- 未增加服务端硬校验或 CLI 运行时警告，避免卡住合法的短通知。

## 5. 验证

- 新增/更新测试覆盖：协议注入与去重、Cindy 规划说明、普通/团队/最终评审通知、

## 6. 升级

1. 更新代码后安装/升级后端与 CLI（editable：`pip install -e dev/agentcli`）。
2. 重启后端，使新的协议与通知文案生效。
3. 重建前端 `npm run build` 或使用发布包。
4. 版本文件统一为 `1.50.1`；`anvil --version` 应为 `1.50.1`。

## 7. 已知边界

- 沟通规范依赖角色自律（协议 + 示例），不做语义或格式硬校验；后续如需更强约束，
  建议先统计违规率再评估。
- 已有 Cindy 的持久化 system_prompt 不会被覆盖；运行时协议是现有安装的生效通道。
- 默认筛选不做浏览器持久化，每次打开任务都回到「对话」。
