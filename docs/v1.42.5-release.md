# Anvil v1.42.5 — 派遣子任务模型修正、回切状态机与 runtime subagent

> 发布日期：2026-11-11
> 版本：1.42.5

## 1. 修正 dispatch 的任务层级

v1.42.0/v1.42.4 把 dispatch 做成了顶层任务，这是错误的。本版本修正为：

- 顶层任务仍只由 human 手动创建；
- dispatch 写入 `parent_id=来源 task`、`parent_step_id=NULL`、`type=dispatch`；
- 它是来源 task 下的非阻塞派遣子任务，不进入 Lobby，只在来源任务的
  「委派/派遣任务」页签展示和追踪；
- Agent 不能通过 dispatch 绕过顶层任务 guardrail。

## 2. 共享 workspace/cwd

- 派遣子任务继承来源 task 的 `workspace_id/repo/base_branch`；
- 使用来源 task 的同一个 workspace 路径/cwd，不创建独立 task workspace 或
  per-run worktree；
- 避免角色从来源切片切到 dispatch 时 cwd 改变，回切时 daemon 误判
  `old_cwd != new_cwd` 而放弃 `--resume`；
- task workspace 清理会跳过被活跃派遣子任务共享的父目录。

## 3. 生命周期

```text
todo → in_progress → done
```

- 角色执行 `anvil task submit` 后直接 `done`，claim 置 `approved`，不进入人工评审；
- 父任务提交守卫、step 委派守卫、`list_delegations` 均排除 dispatch 子任务；
- 父任务 cancel/delete 会关闭/级联清理派遣子任务；
- 派遣子任务不阻塞父 task 或 workflow。

## 4. 路由与开关

- 人类 @ 与显式 `context_mode=dispatch` 不受 `DISPATCH_AUTO_FROM_MENTION` 限制；
- 该开关只控制 Agent 之间的自动派遣：
  - 开：Agent @ 且路由判定 dispatch → 创建派遣子任务；
  - 关：退化为来源 task 的新 slice/回复 run，不建任务；
- 同 task 已有上下文优先复用/切换；角色空闲且请求就在来源 task 时不会被词法低分
  误判为派遣；角色正在其他 task 或跨 task 请求才进入 dispatch；
- Tooling 页面新增「协作与派遣」分组：
  - `dispatch_auto_from_mention`，默认关闭；
  - 文案明确只影响 Agent 自动路由。

## 5. 派遣创建事务与幂等

- `tasks.create` / `runs.create_run` 增加 `commit=False` 路径，dispatch 创建统一提交；
- dispatch insert 捕获唯一约束冲突，回查活跃请求并返回 `reused=True`；
- `source_slice_key IS NULL` 时旧唯一索引失效，迁移为
  `COALESCE(source_slice_key,'')` 表达式索引，并收敛已有重复活跃行；
- 旧顶层 `type=dispatched` 任务迁移为来源 task 下的派遣子任务；找不到来源的
  收敛为 closed/cancelled。

## 6. 回切状态机与看门狗

- watchdog 只在派遣 `return_ready/returning` 或可处理的 `context_return` 状态下短暂
  等待；`open` 派遣、无关 dispatched 子任务、submitted/reviewing 临时 run 不再
  永久抑制来源 step；
- 跨切片回切按 return run 分组，多个临时结果合并为一次 pump；
- wake_note 按 run id 去重，pump 失败有 attempts/backoff/上限；
- submitted/reviewing 临时 run 清标记，不再永久卡住；
- 回切前校验 task/step/slot 和 HITL 等待；等待人工确认的 run 不会被自动 resume；
- `returned` 只在 return run 仍可投递时标记，避免 pump 空转也显示已回切；
- 派遣完成通知/`dispatch.completed` 事件增加幂等标记，崩溃恢复路径也会补发；
- idle release 后 `record_context_return` 会按上下文找回最近 suspended run。

## 7. runtime subagent

- 按运行时 `capabilities.supports_subagents` 注入协议：
  - Claude Code 支持；
  - Codex/Gemini 明确降级为当前 step 串行或 @ 其他角色；
- 同角色当前 step 内的并行探索/实现优先使用运行时 subagent；
  delegation 仅保留跨角色/跨 turn/阻塞式拆工；
- 解析 stream-json 的 Task/Agent tool_use/tool_result，写入 `run_subagents`；
- `/roles/{slug}/runtime` 返回 `active_subagents[]`；
- RoleSessions / TaskDetail 显示「子代理 N」和可观测的 description/结果摘要；
  完整子代理 context 取决于运行时是否暴露 sidechain。

## 8. 角色状态与 UI

- 角色行不再因为没有本任务 run 而 `disabled`/灰化；可展开独立“运行时上下文”面板，
  展示 contexts、session、cwd、队列和 active subagents；
- 修复系统任务 busy 时徽标橙、点灯绿；dead + 有队列时徽标红、点灯绿的不一致；
- 队列优先按 `queue_contexts` 的 task+slice 匹配，避免其他 slice 的排队信息误判；
- 角色等待 `return_ready/returning` 时显示“等待回切”；
- Lobby 只显示顶层任务；派遣子任务不出现在大厅。
