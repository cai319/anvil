## 1. 版本主题

v1.51.1 汇总 v1.51.0 的规划质量改进，并补齐角色建议门禁、收件箱提醒生命周期、
工具治理子页、任务大厅性能与 UI 密度调整。v1.51.0 未单独发布，本说明覆盖完整范围：

1. **Cindy 规划前先澄清**：首次规划阶段通过分轮提问逼近真实意图，产出可确认的
   任务简报，并在对话中确认流程强度与计划形态；未确认简报时服务端拒绝 workflow
   草案。
2. **角色级思考强度**：每个角色的运行时设置新增 `low | medium | high | max`；
   Cindy 默认 `max`，其他角色默认 `high`，通过 Claude Code `--effort` 注入。
3. **角色建议先于工作流审批**：pending 角色建议阻塞工作流；`authorize` 建议批准后
   由 planner 创建/绑定角色，完成前审批保持锁定。
4. **收件箱 @human 生命周期**：按发送角色分别保留提醒，只有人类回复才清除；简报
   确认、board 决策、任务关闭/归档后自动隐藏。
5. **工具治理与体验**：`/tooling` 拆为工具配置/导入/功能开关/运行时提案四个子页；
   任务大厅两阶段加载与批量查询；控件密度、新建任务表单和简报卡收紧。

澄清与角色建议门禁默认开启，边界明确：澄清只影响 Cindy 的首次规划阶段；已有
workflow / 已执行 / 非 todo 任务完全不受影响。

## 2. Cindy 规划前澄清

### 2.1 触发边界

只有同时满足以下条件才进入澄清：

- 任务 `status=todo`；
- 从未有过任何 workflow；
- 无 pending 的 workflow / workflow_revision 草案；
- 无活跃的非 clarify run、无已完成的执行 run；
- planner 解析为 Cindy；
- 不是派生子任务；
- feature flag `cindy_clarification` 开启。

已有 workflow 的任务（含运行中、已终止、已完成）与已执行任务永不进入澄清；
不判 stale、不设门禁、不改变 dispatch / revision / re-plan 行为。

### 2.2 状态与数据

- `tasks.clarification_status`：`none | in_progress | confirmed | skipped | stale`；
- `tasks.intent_brief_json` / `intent_brief_version` / `clarification_round` /
  `clarification_confirmed_at` / `clarification_basis_hash`；
- `task_brief_versions`：草稿、确认、人工编辑、跳过版本；
- 简报字段：目标、真实意图、非目标、约束、验收、假设、开放问题、流程强度、
  计划形态、风险；
- DB 是真相源；任务工作区 `.anvil/intent-brief.json|md` 是投影。

### 2.3 对话与确认

- 新增 `[anvil:clarify]` run 与 `CLARIFY_PROTOCOL`：每轮 1–3 个带推荐答案的问题；
  第一轮给临时理解 + 推荐强度；第 6 轮起 `must_conclude`。
- Cindy 每轮通过 `anvil task clarify <task-id> --file <brief.json>` 更新草稿，
  再 `anvil task mention --to human` 通知并挂起。
- human 在任务会话顶部的任务简报卡确认或跳过；确认/跳过必须由 human token 直接
  触发，文本「确认」不会迁移状态。
- 确认写 `tasks.workflow_weight`（source=human）并自动启动 planner；
  跳过按原样启动 planner，无简报。
- 确认/跳过会先放弃挂起的 `[anvil:clarify]` run，再创建真正的 `[anvil:plan]`
  run；避免复用澄清会话导致「界面说正在规划、实际无人规划」。
- 简报卡只在存在活跃 planner run 时显示「Cindy 正在规划工作流…」；已确认但
  尚未启动时显示「等待启动规划」，规划期间不再重复显示启动按钮。
- 澄清问题卡按消息锁定：该问题之后出现人类回复，或简报已确认/跳过/过期后，
  选项与发送按钮禁用并显示对应状态；刷新或重进任务不会重新激活历史问题。
- 确认后的 weight 会同步写入 workflow 草案树，避免审批页仍显示 Cindy 的旧建议；
  `plan_shape` 由服务端校验结构：`flat` 拒绝 `plan_slices`/`loop`，
  `slices` 要求 `plan_slices + loop`，`auto` 不约束。
- 简报卡保留用户未确认的强度/形态选择，不被 Cindy 的草稿刷新重置。
- 任务定义材料性变更（标题/描述/验收/scope/repo/type/base_branch）→ `stale`，
  发系统 @human 提醒；tags 不算材料性变更。

### 2.4 门禁

- `board.create_draft` / `create_revision_draft`：澄清未确认时拒绝 workflow /
  workflow_revision 草案（409）。
- `planning_conflict` + `POST /runs`：澄清期间禁止直接改 Roster / 拉起执行 run。
- planner prompt 注入「已确认任务简报」强约束块；若 human 新消息与简报冲突，
  Cindy 不产草案，先 @human 说明。

## 3. 角色思考强度

- 角色定义：`definition.runtime.effort = low | medium | high | max`。
- 默认：Cindy（onboarding）`max`；其他角色 `high`；存量角色由
  `effective_config()` 兜底，无需批量迁移。
- Claude Code 运行时在 one-shot 与常驻会话参数中注入 `--effort {{ effort }}`；
  `low/medium/high/max` 已在本机 Claude Code 2.1.332 验证可解析。
- 角色 → 运行时页签新增「思考强度」下拉；保存时保留 `permission_mode`、
  `model_pool` 等其它运行时字段（修复原「保存绑定」会重置运行时配置的问题）。
- 运行中的常驻进程不会热切换；下一次 spawn/resume 或空闲回收后生效。

## 5. 安全与默认姿态

- 确认/跳过/编辑简报/开始澄清 human-only；Cindy 只能写草稿。
- 未确认简报无法创建 workflow 草案；未确认时不能绕过澄清直接执行。
- 澄清只作用于 Cindy 的首次规划阶段；其他角色由用户自行在角色定义里选 skill。
- 不新增人类身份系统；任何 human token 持有者都可确认，冲突需显式裁决。
- 任务简报投影可被执行角色读取；v1 不主动注入 step prompt。

## 9. 角色门禁与收件箱修复

### 9.1 角色建议必须先于工作流审批

- `role_suggestion` 的 `apply_mode` 统一规范化并在创建时校验：缺省/`create_bind`/
  `create+bind` 为创建并绑定，`authorize` 为授权 planner 创建/绑定，其他值 409。
- 工作流审批新增硬门禁：
  - 同任务存在 pending `role_suggestion` → 409，工作流不能先执行；
  - 已批准的 `authorize` 建议中，角色不存在或未绑定到任务 → 409；
  - `workflow_revision` 只受 pending 角色建议阻塞，避免修订引入新角色时死锁。
- `create_bind` 角色建议仍在批准时创建缺失角色并绑定；`authorize` 批准返回结构化
  outcome，并唤醒 planner 执行 `role expand` + `task assign`；绑定完成前工作流
  审批保持锁定。
- `authorize` 的角色创建/绑定状态会写入 planner prompt 的持久待办；即时唤醒失败
  或跳过时，后续 planner run 仍可消费授权。
- Inbox / TaskDetail 显示 apply_mode、请求角色、已有/待创建/已绑定状态与 blocker；
  工作流批准按钮在 blocker 存在时禁用。批准结果会展示创建/绑定/唤醒结果，而不是
  静默刷新。

### 9.2 收件箱 @human 提醒生命周期

- `_mentions` 按 `(task_id, role_slug)` 各自保留最新一条 @human，不再让同任务
  后出现的其他角色提醒覆盖更早、仍未回复的提醒。
- 已处理规则与 scheduler `waiting_for_human` 对齐：只认该 mention 之后
  `role_slug='human'` 的活动；agent/system/workflow 的 comment 不再替人类清掉提醒。
- `clarification.confirmed_at`（confirm/skip/update_brief 都会更新）晚于 mention 时，
  该 mention 从收件箱隐藏；确认后新产生的 mention 仍保留。
- board draft 的 approved/rejected 都可清除对应审批提醒；closed/archived 任务不再
  展示 mention。
- 任务 `in_review` 时，最终评审/问题板条目是唯一收件箱待办；agent 的评审说明仍保留
  在任务时间线，但不再单独生成 `@human` 条目。
- 澄清提示的 detail 改为「请在任务简报卡确认或跳过」；`PUT /clarification/brief`
  补发 task SSE，收件箱无需等 30 秒轮询。
