# Anvil v1.44.1 — context_return 死标记修复与看门狗有界等待

> 发布日期：2026-11-21
> 版本：1.44.1

## 1. 问题

一个已 suspended 的回复 run 在二次 arm 回切时没有复位 `context_returned_at`；
`resolve_context_returns` 只扫描 `after_turn=1 AND returned_at IS NULL`，因此永远看不到
该标记；同时看门狗每 tick 因 `after_turn=1` 抑制步骤 nudge，导致步骤长期 `running`、
`nudge_count=0`，只能人工 restart。

## 2. 修复

- `record_context_return` 支持 re-arm：arm 时复位 `returned_at/attempts/last_attempt_at`
  并更新返回目标；resolver 改为扫描 `after_turn=1`，`returned_at` 仅作审计；
- 新增 `ANVIL_CONTEXT_RETURN_MAX_WAIT_SECONDS`（默认 900s）；TTL 锚定
  `context_return_armed_at`，同目标重复 arm 不刷新，目标变化/人工 restart 才重置；
- 目标 run 长期非 suspended、entry run 长期活跃、attempts 耗尽时，resolver 清标记并写
  `context_return.expired` 审计，不再无限等待；
- resolver 的 claim/clear 带 `armed_at` 代际 CAS：pump 期间若被二次 arm 改了目标，
  旧 resolver 不会误清新标记；
- 看门狗改用 `context_return_is_blocking`，只等待仍可推进的标记；放行 nudge 前原子清
  过期标记，避免 nudge/resolver 双投递；
- 上下文切换把被切走的 running run 落 `suspended`；`_reap_orphaned_step_runs` 纳入
  suspended 的 stale step run，并清理指向它的入站标记；
- 人工 restart：回复 run 重武装自己的回切；步骤 run 清掉所有指向它的入站标记；
  restart 先 pump 目标 run 再补投队列，避免旧 mention/reply 抢在步骤 run 前投递；
- 启动迁移 `schema.context_return_v2` 复位历史 `armed + returned_at` 死标记；
  `schema.context_return_v3` 新增 `context_return_armed_at` 并回填。

## 3. 验证

- `tests/test_auto_return.py`、`tests/test_step_watchdog.py`、`tests/test_daemon.py`、
  `tests/api/test_m4_completion.py` 覆盖死标记、TTL、代际 CAS、restart 顺序；
- 后端全量：`896 passed, 60 skipped`；
- 前端 build 通过。
