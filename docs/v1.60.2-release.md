# v1.60.2 修复：下拉菜单居中、澄清问题送达提示与澄清轮次口径

发布日期：2026-11-28　类型：patch

## 修复

### 1. 所有下拉菜单文字未垂直居中/被上下裁切

- **根因**：原生 `<select>` 的选中值由浏览器在内容盒内垂直居中，`line-height` 无效。
  全局控件给 select 固定了高度（30–36px），`type-scale.css` 又设置 6px 上下 padding，
  而字号经 `font: inherit` 继承正文（15–24px）；border-box 下内容盒可能小于文字行高，
  文字因此被上下裁切。
- **修复**：在最后加载的 `type-scale.css` 末尾统一添加
  `select:not([multiple]) { padding-top: 0 !important; padding-bottom: 0 !important; }`。
  只去掉垂直 padding，保留水平 padding、字号、高度和各页面既有样式；排除多选列表。
- 任务详情「选择角色」、任务简报「强度/形态」等此前零散修复一并收敛，不再逐页打补丁。

### 2. Cindy 提问消息未进入时间线时空窗期没有沙漏

- **根因**：简报草稿与问题 mention 是两次写入；`waiting_for_human` 在 mention 落库时
  即变真，后端随即停止 `thinking`，但前端时间线要等下一次刷新才收到问题消息。
  这段空窗期没有沙漏，输入框却提示「输入你的回答」，容易误以为轮到 human 接管。
- **修复**：任务页检测「澄清中 + waiting_for_human + 简报含开放问题 + 时间线尚无 Cindy
  mention」时保持待送达状态；简报卡继续显示沙漏并提示「Cindy 正在整理澄清问题」；
  输入框占位与底部提示改为等待问题卡，问题真正出现后恢复回答提示。

### 3. 澄清轮次改为只统计 Cindy 主动提出的 grill 问题批次

- **根因**：旧实现每次 human 回复都会启动 clarify run 并 `clarification_round += 1`，
  多次追问/修正会快速消耗轮次。
- **修复**：
  - 澄清轮次上限从 6 调整为 10。
  - run 启动本身不再消耗轮次；只有 planner/Cindy 发给 human、且消息含合法
    `anvil-questions` 问题块的消息才计 1 轮。
  - human 主动发言、@Cindy、补充说明、追问与修正均不计数。
  - 轮次从实际消息派生，并在读取澄清状态/启动 clarify run 时按最近一次
    `clarification.started` 之后的实际问题批次校准，兼容旧数据。
  - 当前任务 `fd1022c5…` 已从旧口径的 3 轮自动校准为实际的 1 轮。
