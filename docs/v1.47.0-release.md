# Anvil v1.47.0 — 安全边界、对象级授权与状态机加固

> 版本：1.47.0（HITL 认证隔离、权限范围、工作流 CAS、知识补全/收割正确性）
> 日期：2026-11-22

## 1. 为什么升级

本版本处理审计发现的 P0/P1 问题，重点是不再让 Agent 获得人类 token、不再允许跨任务/跨频道读写，并修复最终评审驳回回弹、workflow/step 终态竞态、知识 legacy 注入与补全 job 永久挂起等状态机问题。

## 2. 人类认证与 HITL 边界

- 移除公开默认 token（`anvil` / `anvil-web` 不再有效）。
- 每安装生成随机人类 secret：默认 `data/auth-token`（0600），可用 `ANVIL_AUTH_TOKEN` 显式覆盖；显式值必须至少 16 位随机字符，弱 token 拒绝启动。
- Agent 子进程环境剥离 `ANVIL_AUTH_TOKEN`、`ANVIL_AUTH_TOKEN_FILE`、`ANVIL_TEST_AUTH`、`ANVIL_SESSION` 等人类凭据；只允许注入绑定角色/任务的运行级 token。
- Web 首次打开显示 TokenGate，粘贴 `data/auth-token` 完成配对；CLI 自动读取 `ANVIL_TOKEN`、`ANVIL_TOKEN_FILE`、`data/auth-token` 或 `~/.config/Anvil/token`。
- SSE `/events` 改为 human-only；API 响应增加 `X-Frame-Options: DENY`、`frame-ancestors 'none'`、`nosniff`、`no-referrer`。

## 3. 对象级授权与敏感数据

- 任务列表/详情/知识、workflow/replay/dossier、run/context-manifest、board 草稿、agent inbox、role 私有配置/指标、runtime 定义、MCP、频道/主题知识、repo catalog 均校验参与范围。
- 运行级 token 强制绑定单个任务；角色级 token 只返回自己可访问的任务/run/draft。
- MCP `env` 永不通过 API 返回；runtime YAML 仅 human 可读。
- Agent 只能看到已批准知识卡及自己提交的待审内容；不能伪造 `created_by`、`source_role` 或 `normative` 权限。
- repo catalog 对 Agent 隐藏任务/经验样本标题；角色 system prompt 不再对其它 Agent 返回。

## 4. 状态机与并发

- 最终评审驳回写 `review_rejected_at`、唤醒返工角色；scheduler 不再把驳回任务自动推回 `in_review`。
- 最终评审通过收尾活跃 run；scheduler 新增终态任务 run 修复，清理历史 suspended run。
- `submit_step` / `escalate_step` 接入 task lifecycle lock + 状态 CAS；terminate 不覆盖已 completed/failed 的 run/workflow。
- reaper/spawn 使用 `from_statuses` CAS，禁止复活终态 run；委派清理按 workflow execution scope 限定。
- 删除任务清理 parent 委派字段、workflow 关联表、leases、wakes、events、context manifests、action cards 等。

## 5. 知识正确性与收割

- 历史已批准但不完整知识标记 legacy：保留数据与补全入口，但排除出 CIC/自动注入；补全达标后恢复。
- 角色知识补全必须满足必须条款；部分字段返回 422，不再假标记“完成”。
- 统一 `exclusions` ↔ `counterexamples`；已批准 lesson 只允许 legacy 补全，不允许改写成不完整内容。
- 补全 job 增加并发去重、终态不可回退、目标删除清理、TTL/失败对账与 scheduler reconcile。
- Cindy 禁用时知识收割提醒保持 pending，重新启用后补触发；频道收割处理 422/409、限制字段长度；主题卡晋升补齐 insight 字段。
- 任务知识增加真实 `version` 列，`expected_version` 生效；repo/频道知识文件在 reject/deprecate/delete 后同步清理。

## 6. 路径与提示词安全

- 任务/仓库/频道 id 使用安全目录段并做 `relative_to` containment，修复 `.`/`..` 路径穿越。
- 知识收割 prompt 对 task id/repo/workspace 使用 `shlex.quote`；任务标题单行截断并标记为不可信数据。

## 7. 验证

- 后端：`pytest tests -q` — **1032 passed / 63 skipped**
- 前端：`npm run build` 通过
- Live SQLite 只读检查：无点段任务 id、无孤儿补全 job；历史 done 任务的 suspended run 会在新版后端启动后由 scheduler 收尾。

## 8. 升级注意

1. 重启后端，让其生成/读取 `data/auth-token` 并执行 scheduler 修复。
2. Web 首次打开粘贴 `data/auth-token` 内容完成配对；旧 `anvil` / `anvil-web` token 一律 401。
3. 若使用 `ANVIL_AUTH_TOKEN`，请换成至少 16 位随机字符，否则后端拒绝启动。
4. 重新构建前端（`cd dev/frontend && npm run build`）以启用 TokenGate 与安全头。
