# Anvil v1.48.9 — 结构化 feedback_rules 与 workflow 500 兼容修复

> 版本：1.48.9（后端兼容修复；前端无变更）

## 问题

- Windows 实例新建任务（Cindy 自由规划）后，任务详情「工作流」页稳定报
  `工作流加载失败：Error: 500 Internal Server Error`；老任务正常。
- Windows traceback 显示 5 条 `ResponseValidationError`，全部位于
  `definition.feedback_rules`：Cindy 把反馈规则写成了对象数组
  `[{"when": "...", "action": "..."}]`，而 `WorkflowDefinitionOut.feedback_rules`
  要求 `list[str]`。FastAPI 响应序列化阶段因此返回 500。
- 旧任务的历史 workflow 恰好是字符串数组；v1.48.8 新增的错误横幅只是把此前被前端
  吞掉的 500 暴露出来（此前显示为“没有工作流”）。
- 同类未校验字段还有 `definition.verification`、step `acceptance` 等，存在相同的 500 风险。

## 修复

- 新增 `anvil/workflow_payload.py`：在写入与读取边界统一收敛工作流载荷形状：
  - `feedback_rules` 对象项扁平化为 `"when：action"` 字符串；
  - `verification` 支持对象、`{cell: method}` 映射、字符串，统一为验证矩阵数组；
  - step `acceptance` / `depends_on` / `on_reject` / `escalate` / `scope_paths` /
    `evidence` / `decision_options` 做列表与条目类型兜底；
  - 非法 `status` / `weight` / `decision_authority` 等字面量兜底；
  - 仅在发生转换时按字段去重记录 WARNING，重复轮询不刷屏；已规范数据完全幂等。
- 读取路径：`get_workflow`、`list_for_task`、pending revision、metrics 接入规范化。
- 响应模型安全网：`WorkflowOut` / `WorkflowHistoryOut` 增加 before-validator，
  绕过 `get_workflow` 的返回路径也不会再因字段形状 500。
- 写入路径：`normalize_definition` 在落库前规范化 top-level feedback_rules / verification，
  并把非列表 acceptance 收敛为列表；新任务不再写入对象反馈规则。
- `acceptance` 的对象条目（如 `{"criterion": "...", "status": "unmet"}`）在数据库中保留结构，
  供 review packet 读取状态；仅在 API 响应中扁平化为可读字符串。
- 规划提示词明确 `feedback_rules` 为字符串数组（每项「当…时：…」），减少再次出现；
  提示词快照同步更新。

## 验证

- 用与 Windows traceback 相同的对象 `feedback_rules` 端到端复现：
  修复前 `GET /tasks/{id}/workflow` 500，修复后 200 且字段已扁平化。
