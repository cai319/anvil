# v1.60.0 执行沙箱与受控 PoC 运行

发布日期：2026-11-28　类型：minor（默认行为变更）

## 摘要

v1.60 把「角色执行」与「PoC/动态验证」纳入 OS 级沙箱，并把不可信代码执行从角色自觉
升级为可审批、可复现、可取证的一次性作业：

- **standard 档**：普通角色 run/工作流步骤；工作区写范围、资源上限、进程树回收、
  Anvil 秘密定向读拒绝；网络不限制（单用户信任模型，明确文档化）。
- **strict 档**：PoC/动态验证/RSI 验证命令；一次性作业、默认断网、只读源码快照、
  固定资源/时限、产物 sha256 回传。
- **平台**：macOS 用 Seatbelt（标准档）+ Docker/Podman（严格档）；Windows 用命名
  Job Object（标准档）+ 默认 WSL2 发行版 + 专用用户 + bubblewrap（严格档）。
- **PoC 运行器**：`poc.json` 规范、safe/relaxed 审批、finding「已验证」派生、
  收件箱审批、finding 抽屉作业卡。
- **其余执行点**：MCP 服务器探针走标准档；RSI replay 验证命令走严格档。

## 安全模型

- 威胁模型：本机单用户，保护宿主文件/凭证/内核/其它进程；不做多租户。
- **standard 档**不是完整读隔离：宿主普通文件仍可读；它保证工作区写范围、资源上限、
  进程树，以及 `data/auth-token`、SQLite、备份、其它任务/角色数据的定向读拒绝
  （能力允许时）。**strict 档才是不可信代码的强隔离边界。**
- `ANVIL_SANDBOX=host-unsafe` 显式关闭沙箱，记审计并常驻警示；严格档默认仍不执行。
- 模型凭证仍走继承的环境变量；沙箱内 `HOME` 指向 `<workspace>/.anvil/home`。
  依赖交互登录的用户需改用 API key 或受控导入凭证（见故障排查）。
- 单一 human token 模型、`bypassPermissions` 默认、HITL 端点与 SSE token 例外均不变。

### 残余风险（必须知晓）

1. Windows standard 的写范围/读拒绝依赖 AppContainer/受限令牌；不可用时降级为
   资源隔离 + 能力横幅，此时 human token 对角色可读。
2. macOS `sandbox-exec` 已弃用但当前仍可用；未来移除时 standard 降级为 host。
3. standard 档网络不限制：被提示注入的角色仍可外发数据；不可信代码必须进 strict。
4. Windows WSL/Docker 严格档、Windows Job Object 真实进程树必须在 Windows QA 机
   按 `docs/superpowers/specs/2026-11-28-windows-sandbox-qa.md` 验收后再发布安装包。

## 新增能力

### 执行沙箱（M0/M1）

- 持久角色 spawn 经 `SandboxBackend`；沙箱实例与上下文槽对齐，`round`/策略摘要变化
  在 turn 边界重建。
- macOS Seatbelt：写白名单（工作区/worktree、角色 home、实例 TMP、当前 repo `.git`）
  + 定向读拒绝；supervisor 5s/60s 采样，超限杀进程树并标 `sandbox_resource_*`。
- Windows 命名 Job Object（launcher 先入 Job 再 spawn），修复 v1.51 持久进程只杀根
  进程的缺口。
- 状态/自检：治理页能力矩阵、Run 详情沙箱卡、`GET /api/v1/sandbox/status`、
  `POST /api/v1/sandbox/self-check`。
- 功能开关 `sandbox`（安全分组，默认开启）；`ANVIL_SANDBOX=host-unsafe` 优先。

### 受控 PoC（M2a/M2b）

- `POST /api/v1/poc-jobs`：agent 可创建绑定任务/ finding 的 **safe** 作业；relaxed
  （联网/放宽资源/非默认镜像）进入 `waiting_approval`，人工批准/驳回后执行。
- 作业 spec：`prepare`/`build`/`run` 阶段、每命令超时/env 白名单、`expect`
  （exit/signal/stdout）、产物 glob 与单文件/总量上限；hard max 4h/16GiB/1024 PIDs。
- 快照：任务工作区复制到作业目录（排除 `.git`/`.anvil`/依赖目录），只读挂载；
  记录 tree hash；失败作业同样保留产物与日志。
- 证据：backend/image/network/tree hash/phases/exit/signal/峰值/artifact sha256/
  `verified`；finding 派生 `verification`（不改手工 `poc_status`）。
- 配额：每任务/角色 running ≤2、排队 ≤20；`sandbox_*` 失败不自动重试。
- 保留：作业元数据 180 天；任务归档/删除时清理产物/日志目录，保留 evidence 与
  sha256；每日清理过期作业/实例目录。

### Windows 严格档（M3）

- 复用默认 WSL2 发行版，不新建发行版；每次作业独立 mount/network namespace，
  只暴露 `/src`、`/job`、ext4 `/scratch`、`/out`，隐藏 `/mnt` 与 home。
- `anvil sandbox provision --consent`（或治理页按钮）一次性安装 bubblewrap/工具链、
  创建 `anvil-sbx`、写 marker；Ubuntu 24.04 userns 受限时安装 AppArmor profile。
- 资源：`prlimit` + 作业超时；超时 `pkill -u anvil-sbx`；产物经安全 tar 导出。

### RSI / MCP（M4）

- RSI replay 验证命令在 strict 作业中执行；strict 不可用且非 host-unsafe 时判
  `inconclusive`，不误评分。
- MCP stdio 探针经 standard 沙箱启动，临时 prober home，`finally` 回收。

### CLI / UI

- CLI：`anvil poc template|run|list|show|logs|artifacts|cancel`；
  `anvil sandbox status|self-check|provision`。
- UI：Run 详情沙箱卡；治理页底座/能力/自检/WSL 准备；finding 抽屉 PoC 运行卡
  （新建/日志/证据/产物/取消/审批）；问题板「已验证」chip；收件箱 PoC 审批。

## 升级

1. 停止服务，替换安装包/代码，重启（会终止所有常驻角色进程；上下文槽保留，下次
   `--resume`）。
2. `anvil sandbox status` 查看底座：
   - macOS/Linux：安装 Docker Desktop/OrbStack/Podman；首次 PoC 自动构建工具链镜像。
   - Windows：启用 WSL2 与默认发行版；执行 `anvil sandbox provision --consent`
     （root 配置，审计可见）。
3. 缺严格档底座时 safe PoC 返回 409 `strict_sandbox_unavailable`；普通角色执行仍可用
   standard 档。只有显式 `ANVIL_SANDBOX=host-unsafe` 才回退宿主直跑。
4. 现有登录型 CLI 用户：沙箱 HOME 重定向后若无法认证，改用 API key 环境变量或按
   故障排查导入凭证；`host-unsafe` 可临时恢复旧行为。
5. 版本号已 bump 到 1.60.0（`dev/VERSION`、backend/CLI package、前端 package）。

## 已知限制

- Windows standard 的写范围/读拒绝为 best effort（AppContainer spike 结果决定）。
- Docker/WSL 真实容器链路未在开发机（macOS 无 Docker）验收；发布 Windows 安装包前
  必须完成 QA 清单。
- standard 档网络不限制；strict 联网需人工批准（v1.60 不做域名允许清单代理）。
- 作业并发为 1（单 worker）；高并发 PoC 后续版本再扩展。
