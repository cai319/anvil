# Anvil v1.48.7 — 角色删除契约与历史显示快照

> 版本：1.48.7（角色删除与历史展示修复；新增 `role_snapshots` 表）

## 修复

- 删除角色前检查活跃 run（`created/projecting/running/submitted/reviewing/suspended`）：
  - 仍有活跃 run 时返回 **409**，角色和 run 保持不变；
  - 先释放 run 后才能删除。
- 无活跃 run 的角色执行硬删除，但保留最小展示快照 `role_snapshots`（slug、名称、头像、删除时间），不保留权限或运行配置。
- 新增 `GET /roles?include_deleted=true`：返回活跃角色 + 已删除角色的展示快照，快照带 `deleted=true`；默认 `GET /roles` 仍只返回活跃角色。
- 启动清理：
  - 对历史任务/run 仍引用、但角色已删除的 slug，从 `role_versions` 回填名称/头像快照；
  - 将角色已删除但 run 仍活跃的残留会话标为 `abandoned`，保留历史并清理进程。
- `GET /runs?active=true` 过滤角色已不存在的 run；任务大厅也按当前活跃角色再次过滤，实时会话不再显示幽灵角色。
- 角色相关接口防护：
  - `POST /runs`、任务创建/指派/派发等接口对已删除角色返回明确 4xx；
  - `mention` 对已删除角色只记录，不唤醒、不创建 run；
  - 历史 run、任务、workflow 和角色接口的读取仍可追溯。

## 前端

- Lobby、TaskDetail、TaskReplay 使用 `include_deleted=true` 解析历史角色名称/头像。
- 新建任务、任务指派、@ 提及候选只使用活跃角色。
- 删除角色确认文案提示：若仍有活跃会话/运行，请先释放。

## 验证

- 新增 TDD 契约测试 `dev/tests/api/test_role_deletion_contract.py`，覆盖删除拦截、快照、角色接口矩阵、任务/run 接口、启动回填和孤儿清理。
- 后端全量：**1089 passed, 63 skipped**。
- 前端 `npm run build` 通过。
- 真实数据验证：4 个已删除角色回填快照；21 条旧孤儿活跃 run 转 `abandoned`；大厅实时会话只保留现存角色。

## 升级

- 重启后端触发 `role_snapshots` 建表和启动清理。
- 替换前端静态资源；版本文件统一为 `1.48.7`，`anvil --version` 输出 `1.48.7`。
- 已删除角色的详情页 `/agents/<slug>` 仍不可访问；快照仅用于任务和历史展示，不恢复角色操作能力。
