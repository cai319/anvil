# v1.62.0 引擎执行验收检查与切片契约锁定

发布日期：2026-11-28　类型：minor（默认工作流行为增强）

## 摘要

v1.62 把可机械化的验收从 agent 判断变成系统事实：切片 scope 由 verify 角色写出结构化
spec 并锁定检查与接口，引擎在 base 上跑红、在 verify 上跑绿；verify 只整理证据，
decide 逐项记录判定。历史上 gate packet 的验收状态长期为 `unknown`、decide 从未驳回，
本版让「完成」有可执行依据，而不是执行方自述。

- **引擎执行检查**：test / command / file_assert 由引擎以 sandbox job 执行；
  manual 项不执行，交给 decide 判定。
- **合法红 vs harness 错误**：只有 `AssertionError` / `NotImplementedError` 算合法红；
  导入/收集、用法、超时、信号是 harness 错误，不消耗 fix 预算。
- **切片契约锁定**：scope 提交结构化 spec；测试文件、运行器配置、测试依赖组与
  stub 签名锁定；execute 的 `scope_paths` 必须与锁定集合不相交。
- **plan 人工门**：`plan_slices` 可选人工门，展示切片表、Brief 覆盖矩阵、manual 预估
  与 enabling 标记，批准后才展开。
- **逐项判定**：decide 记录 `met / unmet / n.a.` 与证据引用；`unknown` 阻止通过；
  manual 占比超过 30% 时该片判权归 human。
- **显式 replan**：改验收只能走 `anvil step replan`；删除检查、降级为 manual、
  改断言但无新红证据属于弱化，需人工批准。
- **检查台账与指标**：`anvil workflow ledger` 汇总 N_total、有效红、harness 比例、
  可机械化占比、返工与 replan 计数。
- **运行上限**：每片 diff 与每任务时长超限升级人工，不硬失败。

## 新增能力

### 1. 检查作业执行与取证

- 检查种类：`test`、`command`、`file_assert`、`manual`；manual 不执行。
- 引擎记录：检查 id、命令、退出码、信号、超时、junit 摘要、收集到的测试数、运行 id、
  环境哈希与依赖摘要。证据只由引擎写入，agent 不能覆盖或伪造。
- pytest 适配器：`--collect-only` 记录测试数基线；退出码 5（未收集到测试）判 harness
  错误；统一 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`，所需插件由 spec 以 `-p` 锁定；
  扫描依赖 delta 中的 `pytest11` entry point。
- `command` 必须在 spec 中声明断言失败退出码，否则无法锁定；`file_assert` 由引擎原生
  实现（`path` + `contains`）。
- 失败分类：`check_failed`（断言失败）、`check_signal`（信号）、`check_timeout`
  （超时）、`check_error`（harness/执行错误）。

### 2. 切片 spec 与锁定集合

- scope 步骤用 `anvil step submit ... --slice-spec-file` 提交 spec：验收项
  （kind/criterion/verification/evidence）、seam、out-of-scope、contract、
  deliverable 路径与 stub 签名。
- 绿地切片写统一抛 `NotImplementedError` 的接口 stub；stub 签名以 AST 哈希锁定，
  execute 只填函数体。
- 锁定集合：测试文件、运行器配置段、独立 runner 配置文件、测试依赖组、stub 签名、
  spec 哈希与基础环境哈希。execute 的 `scope_paths` 与锁定集合不相交才能锁定。
- 生产依赖允许变化但记录 delta；测试依赖闭包变化升级人工。生产依赖变化时引擎在
  base 代码 + 新依赖集上重跑反事实检验：变成通过判检查失效，变成 harness 错误升级人工。

### 3. plan 门禁与 Brief 覆盖矩阵

- `plan_slices` 可设为可选人工门（本版唯一的门禁规则放宽）。提交后只保存 `plan_json`
  并生成评审包，human 批准后才展开；未批准不产生可执行步骤。
- 评审包展示切片表、Brief 覆盖矩阵（每条 Brief acceptance 被切片覆盖或被显式
  deferred 并写明理由）、manual 预估、enabling 标记与依赖边。
- non-goals 与各切片 out-of-scope / `scope_paths` 交叉校验。
- enabling 切片只能在 plan 审批时声明，运行时追加一律拒绝。

### 4. verify 绿跑与 decide 判定链

- verify 阶段由引擎重跑同一检查：测试数少于基线或新增 skip 直接判失败；绿跑必须使用
  与红跑一致的基础环境哈希。
- verify 只整理证据，不提交「已通过」结论；判定由 decide 记录。
- decide 用 `--verdicts-file` 逐项记录 `met / unmet / n.a.` 与证据引用；存在 `unknown`
  或 `unmet` 不允许通过。引擎项状态不可覆盖，manual 项由 decide 判定。
- manual 占比在 scope 锁定时重算；超过 30% 时该片 decide authority 切为 human。
- 新 loop 模板强制 `decide.role ≠ verify.role`；存量 equal-role 模板使用按阶段隔离的
  上下文槽（role, task, slice, stage），避免同一会话自写自判。

### 5. 显式 replan 与弱化检测

- `anvil step replan` 复用 reject-to-ancestor 重置，必须写原因并记录新旧 spec 哈希；
  scope 与下游回到 `pending`，之后必须重新提交 spec 并重跑红校验。
- 弱化 diff（删除检查、检查降为 manual、修改断言但无新红证据）无论流程强度都需要
  human 批准；每片最多 1 次 replan，第二次升级人工。
- human-only override 明确记录，不静默放行。

### 6. 检查台账与运行上限

- `anvil workflow ledger <wf> [--json]` 输出 N_total、N_qualified、有效红占比、
  harness 错误红占比、可机械化占比（按 test/command/file_assert/manual 分列）、
  假通过输入、人工返工、human authority 片占比与 replan/弱化计数。
- 运行上限为运行参数，不是预注册阈值：每片 diff 行数与每任务总时长超限时升级到
  human 收件箱，不硬失败。

## 新增 / 变更 CLI

```bash
# 引擎验收检查
anvil check template [--kind test|command|file_assert]
anvil check run --file check.json [--task <id>] [--wait] [--json]
anvil check list|show|result|logs|artifacts|cancel ...

# 切片 spec / 逐项判定 / replan
anvil step submit <wf> <scope-step> --summary "..." --slice-spec-file spec.json
anvil step decide <wf> <decision-step> --approve --verdicts-file verdicts.json
anvil step replan <wf> <slice-step> --reason "..." \
  [--slice-spec-file spec-v2.json] [--red-evidence JOB,...] [--approve]

# 检查台账
anvil workflow ledger <wf> [--json]
```

- `anvil check` 走 standard 档沙箱，默认 `network=none`；需要联网/放宽资源时按
  ADR-0003 人工批准。Agent 只能绑定自己可读的任务；队列配额满时返回 HTTP 429。
- UI：plan gate 卡展示切片表、覆盖矩阵、manual 预估与 enabling 标记；run 详情展示
  引擎检查结果与逐项判定；收件箱承载超限/弱化 replan 等人工升级。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ANVIL_DIFF_CAP_LINES` | `400` | 每片 diff 行数上限（0=不限）；超限升级人工 |
| `ANVIL_TASK_DURATION_CAP_SECONDS` | `0` | 每任务总时长上限（秒；0=只记录、不升级） |
| `ANVIL_RUN_CAP_ENFORCE` | `1` | `1`=超限升级人工；`0`=只记录不执行（试点阶段一） |

diff 上限初始为 400 行占位，试点阶段一按 P90 重算；时长上限在阶段二基线运行后定值。
调整这两项不需要新 ADR，但阈值改动需新 ADR。

## 升级

1. 停止后端并备份 `data/`，替换代码/安装包；
2. 重新执行 `pip install -r backend/requirements.txt` 与 `pip install -e agentcli`；
   重启后端，`init_schema` 幂等补齐检查作业、切片 spec/锁定、逐项判定与台账字段/表；
3. `cd dev/frontend && npm run rebuild` 后重启；
4. `anvil --version` 应为 `1.62.0`；`anvil check template` 与
   `anvil workflow ledger <wf> --json` 可用；
5. 存量 equal-role 模板无需手工迁移，decide 会自动使用 stage 上下文槽；新模板应配置
   `decide.role ≠ verify.role`。

上一发布版 v1.60.2 的沙箱与澄清修复不变，详见对应发布说明。

## 验证

- 后端：`cd dev && pytest tests/ -q` → **1550 passed / 64 skipped**。
- 前端：`cd dev/frontend && npm run build` → 通过。
- CLI：`anvil --version` → `anvil 1.62.0`；`anvil check -h`、`anvil step replan -h`、
  `anvil workflow ledger -h` 显示新动作与示例。
- 集成场景覆盖：plan gate 批准/拒绝与展开时机、锁定集合不相交、合法红 vs harness
  错误、测试数下降/新增 skip、环境哈希不一致、反事实重验三种结果、逐项判定与
  `unknown` 阻止、manual 比例切换、decide=verify stage 槽、replan 弱化/次数上限、
  Brief 覆盖缺口与 enabling 运行时追加、diff/时长超限升级。

## 已知限制

- **manual 项仍由 agent 判定**：decide 分离与 30% 比例阈值只能降低风险，不能消除。
- **训练数据泄漏**：公开项目的缺陷可能已在模型知识中，试点探针无法消除。
- **上下文隔离不等于模型错误隔离**：不同角色仍是同一模型，可能犯同类错误。
- **生产依赖中的自动加载插件**：已用 `PYTEST_DISABLE_PLUGIN_AUTOLOAD` 与 entry point
  扫描缓解，仍属残留风险。
- **试点性质**：本版只交付机制；阶段一红校验探针与阶段二同任务双跑尚未执行，
  阈值与结论不能提前解读。阶段二通过只代表「可以扩大试点」。
- 多语言 runner 适配器目前只有 pytest、通用 command 与引擎原生 file_assert。
